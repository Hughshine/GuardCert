\section{CompCert Case Study: Optimistic Affine Loops}
\label{sec:case-study}

The case study tests the interfaces against real Clight execution and memory.
PolCert supplies a capability reference for affine domains, candidate schedules,
and tiling; the integration uses GuardCert's own source/guard adapters together
with the existing vendored optimizer proof infrastructure. The concrete toolchain
is pinned to CompCert~3.18, Rocq~9.2, and Stdlib~9.2.

\subsection{Established Compiler Path}

The current complete path supports a loaded signed root bound with a constant
offset and canonical affine descendants. It captures the initial header word,
executes private numeric and memory checks, validates an untrusted candidate,
and retains the original source on refusal. Candidates include schedule
reordering and supported tiling/domain witnesses; successful checking binds the
candidate to the actual source description.

For this path, \code{compile_offset_affine_multi_regions_correct} proves that a
successful compiler result is related to the original Csem program by a
backward simulation into CompCert assembly semantics. The proof composes
SimplExpr, SimplLocals, the expression-region host, and the verified backend.
The region contracts and host progress obligations determine the source class;
the theorem is not a license to install arbitrary Clight fragments.

\paragraph{Candidate production and the connected affine successor.}
The earlier native routes propose a candidate Loop AST through built-in
policies or external input. They use PolCert extraction and polyhedral
correspondence/dependence validation before concrete lowering and guarded
installation. The memory instance's external scheduler and phase-export hooks
still refuse; the older prepared optimizer adapter is proved separately but is
not called by those C drivers. These results establish conditional candidate
validation, not an installed automatic scheduling/code-generation pipeline.

The selected frontend now uses paired \code{\#pragma}\ \code{scop} and
\code{\#pragma}\ \code{endscop} markers. It records fresh label identities
before elaboration and retains them through normalization. The new Clight host
restricts discovery and installation to selected occurrences; filtering a
structural AST table alone could otherwise rewrite an identical unmarked loop.
It proves identity on unselected subtrees and a whole-program simulation under
the existing region, progress and resource contracts. The resulting compiler
endpoint, \code{compile_selected_tensor_literal_regions_correct}, composes to
Csem-to-Asm while reusing the literal tensor guard and candidate validation.
The native metadata pass lies at the parser/elaborator boundary; this is not a
new verified Cabs-to-Cabs pass. Direct declarations in a marked span refuse
selection so a new surrounding block cannot shorten their scope. Malformed
marker pairs also preserve their whole original function.

A marker requests an attempt and supplies no semantic assumption. A connected
successor now exports the checked family's canonical source model, invokes
Pluto on OpenScop, imports and validates the affine schedule, and calls
PolCert's proved prepared code generator. The installed candidate Loop comes
from that generator. The final existing mapped-domain factory rechecks it and
supplies forward execution and progress; the selected compiler's theorem
already permits an arbitrary data-only proposer. Source, scheduled model,
generated Loop and phase receipts are retained alongside actual Clight output.

Pluto retains the original order on the evaluated tensor examples. A further
untrusted layout phase reads the affine WRITE matrix and proposes traversal in
logical coordinate order: a column-order address yields a nonidentity
$(j,i,k)$ schedule. This phase constructs a scattering matrix, rather than
target Loop code; the same validator, prepared codegen and final factory check
its result. The generic kernel is unchanged, while the domain supplies the
model/transition obligations and the language host supplies installation.

Two new bridge theorems map completed generated execution back to the source
model and source Loop. They are backward correspondence results; they do not
replace the factory's progress proof. The route reuses compatible extractor,
affine-validator and prepared-codegen components, rather than literally calling
the frozen older \code{Opt_prepared} objects. Strengthening and combined
loaded-header/dynamic-layout integration remain pending.

A tiled successor carries the actual proposed Loop and point-space witness
data, rather than reconstructing a fixed target from tile sizes. It validates
the affine and tiling phases and runs prepared codegen on the transformed
point space. An actual C probe exposed a further boundary: codegen emits
\code{min/max/floordiv} bounds, while the source extractor accepts affine bounds.
An untrusted adapter keeps the generated loop skeleton and instruction arguments,
proposes affine enclosing bounds, and adds affine membership guards. For positive
$d$, it encodes $q<\lfloor e/d\rfloor$ as $d(q+1)\leq e$.
The final checker validates the adapted candidate's complete correspondence with
the assumed source; it trusts neither the proposed bounds nor that identity.
Both raw and adapted Loop outputs are retained. No separate raw-to-adapted
equivalence theorem is claimed. The codegen backward theorem concerns the raw
output; the installed candidate obtains forward execution and public-exit
restoration from its own checked certificate. The same guard encoding and
selected-region language host are reused, with an unchanged generic kernel.

\subsection{Original Sources and Typed Data: Current Boundary}
\label{sec:original-source-boundary}

The pinned PolCert C harnesses use double arrays and scalars, long-long loop
controls, and global multidimensional arrays. The original serial BT source
adds loaded global dimensions, inclusive tests, nonzero starts, scalar
temporaries and multiple loop regions. These are implementation targets; the
installed signed32 memory families do not cover them merely because ordinary
CompCert compilation succeeds. The first original-source attempts in
Section~\ref{sec:evaluation} expose this boundary without replacing those
computations with integer fixtures.

A new memory instruction functor separates explicit access footprints from
value computation. The closed double instance evaluates bit constants,
loaded operands, addition, subtraction, multiplication, division and negation
using CompCert's IEEE operations. It reuses the existing independent-footprint
exchange proof for arbitrary memory chunks: independent actions observe the
same operands and retain each expression's operation tree. No floating-point
associativity or real-number model is assumed. For matrix multiplication,
dependencies on each output still constrain traversal order; this foundation
does not authorize reassociation or parallel reduction.

The current expression bridge is forward: typed operand-evaluation receipts,
emitted expression code and model evaluation imply actual Clight expression
evaluation. It is not an original-source decoder or a bidirectional equivalence
result. Original Clight-to-model correspondence, eight-byte Mfloat64 addressing
and checks, Int64 control correspondence, typed candidate lowering and selected
factory installation remain open. The kernel is unchanged. The language
instance supplies concrete value/memory/control and entry/exit proofs; the
optimizer supplies source modeling, assumptions and candidate validation.
The eventual site producer must discharge these obligations from the checked
source rather than require semantic callbacks from a C programmer.

\subsection{Nested Loaded Bounds and Actual Candidate Execution}

An adapted Figure~2 source from OLO~\cite{olo2017} supplies the concrete
source for the new nested compiler:
\begin{lstlisting}[language=C]
for (row = 0; row < shape[0] + 1; row++)
  for (column = 0; column < shape[1] + 1; column++)
    for (component = 0; component < 5; component++)
      output[(row * 16 + column) * 5 + component] =
          row + column + component;
\end{lstlisting}
This preserves the three-level control pattern and two repeatedly loaded
headers. It uses a flat fixed layout and an arithmetic store body; it is not
the full NAS BT kernel. The output may alias either header. A store can then
change the next source test, so the captured iteration domain need not describe
the original execution until preservation has been established.

The language services first capture the outer header. They capture the child
header only if the actual outer test is active. An empty outer loop therefore
requires neither a defined child counter nor a readable second header. The
source's modular \code{Int.add} computation is kept distinct from the raw memory
observation; no-wrap facts belong to the accepted modeling condition.

For an active prefix, the proof retains a witness in the memory actually reached
by the source. It transports access permissions back to the guard-entry memory,
not loaded data values. Each accepted body check must protect \emph{all} captured
observations before the next child test is justified. Completion of those checks
for the current row permits the next outer test. Only after this preservation
chain can the proof derive execution of the cached source and consume the
affine candidate certificate.

A data-only site checker binds the actual original AST, source scope, private
caches and helpers, checked memory leaf, scan namespace, and component lowering.
It rejects a cached model offered as the original source. A runtime
\(\mathit{row}=0\) gate enforces the supported initial-row profile and skips all
header reads on refusal. Two positive-count gates bypass the numeric probe when
the outer or child loop is inactive. In the active case, original-source
completion supplies the first actual leaf; checked parameter use derives the
words needed by the numeric probe. Its accepted domains and word views name the
actual check exit, rather than a hypothetical cached-source entry.

The assembled guard then executes two private helper assignments and the
complete outer short-circuit scan. Preparation preserves the original source
and public exits, and produces fresh numeric, header, and prefix facts at the
new scan entry. All static and dynamic inputs of the scan are discharged from
the checked site and these execution receipts; no additional header, effect,
definedness, or source/model execution callback is required. Generated code uses
fixed observer address expressions. A syntax equality proves that runtime
blocks, offsets, and raw-word witnesses do not change the complete scan AST.

At each reached constant subbody, the domain library derives guard-entry access
permissions from actual source execution. The language library implements
address comparisons against both captured words. Acceptance separates every
point write from both observations, preserves them through the actual subbody,
and licenses the next child test. Completion of each row licenses the next
outer test. Refusal stops the enclosing prefix before its increment; later
bodies need no permissions. A separate concrete fixture proves all five original
stores and their scan, including overlap refusal and adjacent disjoint regions
inside one allocation. This fixture supplies a body-level result, rather than
an installed enclosing optimizer.

Full acceptance now produces cached-source execution and the canonical
three-axis Clight model with the same final memory and public exit. The existing
verified package decoder connects that actual model execution to Loop semantics
when its data lowering succeeds. The model entry is kept distinct from private
guard cursors and explicitly framed to the actual guard exit. The local safety
theorem consumes original \emph{silent normal completion}. Header stability is an
acceptance result, never a premise used to execute the guard.

The nested adapter now transports canonical execution to the actual check exit
before executing the existing multi-array alias guard. Acceptance produces a
private model anchor and its frame to the checked candidate entry. Quiet
determinacy makes the anchor valid for every completed source execution at that
entry. The adapter consumes the existing candidate certificate and actual
lowering result, restores public exits, and invokes the unchanged kernel's
guarded-preservation theorem. No source/model semantic callback is supplied by
the source proposer.

The checked factory connects this local proof to the existing projected-region
contract and signed-expression host, including typed private resources and
source progress checking. The new \code{compile_ncs_multi_regions_correct}
endpoint establishes Csem-to-Asm backward simulation for successful compilation.
A fixture confirms that the original three-level AST passes the host's progress
check; whole-program installation remains a language-host theorem rather than
a consequence of the local completion domain alone.

The actual C frontend retains a zero-offset address in \code{shape[0]} and
skip-prefixed counter resets. Language lemmas prove execution equivalence for
these forms, preserving trace, memory, and outcomes; an untrusted matcher cannot
erase them without this correspondence. The frontend factory checks the actual
AST, reuses the normalized nested instance, and restores the original frontend
AST as fallback. An untrusted descriptor proposes the shape, private names, and
candidate data. The checked factory, rather than a semantic callback from that
descriptor, produces the local contract.

The extracted driver calls the frontend compiler whose endpoint is
\code{compile_ncs_frontend_regions_correct}. Successful compilation has the same
Csem-to-Asm conclusion through the existing language host. On the unchanged
adapted source, identity, interchange, and $2\times3$ tiling install candidates;
disabled and invalid proposals retain the original loops. Observations of
unmodified assembly distinguish the reordered traversals from source execution
and confirm source behavior on header-alias fallback (Section~\ref{sec:evaluation}).
This establishes the functional path for the fixed-layout profile, not the full
BT kernel or a result about guard affordability.

Additional C programs use the same compiler entry and source descriptor for
in-place array updates, reads from two arrays with writes to a third, two guarded
sites in one function, and global effects and returns around a region. Disjoint
slices within one allocation execute reordered candidates; equal or shifted
data pointers follow the source fallback. Empty paths also exercise a scalar
defined only when the body is reached. None of these tests changes the kernel,
language proofs, or candidate producer.

A chain body reads \code{a[index+75]} before writing \code{a[index]}, where
\code{index=80*row+5*column+component}. The offset corresponds to
$(\mathit{row}+1,\mathit{column}-1,\mathit{component})$ and can cross the proposed
traversal order. The checked pipeline retains the original chain for interchange
and tiling. Separate unguarded C variants compiled to assembly change 30 and five
output words on one input, respectively. This supplies a concrete dependence
counterexample, rather than only invalid-metadata tests; the observation records
pipeline refusal without identifying an internal rejection branch.

The proposer can instead restrict the child-count profile to $[1,2)$ while
retaining the root range $[1,5)$. The same checker then accepts the chain's
interchange and tiling candidates. The same guard producer encodes the tighter
premise: a three-row, one-column input executes the candidate, whereas the
counterexample input executes the original AST. The condition still includes
safe capture and header preservation; the child range alone is not the complete
guard. This demonstrates how an instance-proposed sufficient premise enables a
conditional rewrite, without generic weakest-precondition inference.

\subsection{Condition Expressiveness and Reuse}

A new source-checked condition handles redundant signed32 RMWs. For
$a[q] \mathrel{:=} a[q]+\alpha$, a successful original addition establishes
that \code{alpha} contains a word. This licenses a pure equality test against
zero without a memory probe or a no-overflow assumption. The syntax checker
protects \code{alpha} and recognizes the exact redundant RMW through finite
sequences, branches and loops. On acceptance, its execution theorem preserves
every previously defined \code{Mint32} observation, including aliased headers
with different raw values. It does not assert equality of arbitrary bytes,
other chunks or the entire memory. The resulting encoding certificate has
the existing \code{readonly\_condition} type; the minimal kernel is unchanged.
The loaded-Horner source passes this checker, and an actual aliasing execution
preserves headers 2 and 3 while the old separation tree refuses. The successor loaded-word factory now installs this condition. A positive
original root/child/literal path supplies an actual first RMW and licenses the
scalar read before any body write. The zero path initializes private helper and
flag state without scanning memory; the nonzero path retains the historical
scan. Value preservation supplies original-to-cached execution, and private
frames transport it through helper initialization to canonical execution at the
actual check exit. Empty and refused profiles bypass the scalar check.

A reusable Clight preparation certificate records this execution, its original
footprint frame and accepted canonical execution. It is produced by checked
source factories, not supplied as an optimizer's semantic callback. The common
complete-condition/candidate adapter then derives the projected region
contract, and the existing selected host proves installation. The new selected
compiler has a Csem-to-Asm backward-simulation theorem. This connection changes
neither the minimal kernel nor the actual generated-candidate interface.
Acceptance, scan work and complete runtime cost are evaluated separately below.

A positive-offset service derives an arithmetic presumption from the actual
captured word. For signed words $r,d$, if $\mathrm{signed}(d)\geq0$ and
$\mathrm{signed}(\mathrm{add}(r,d))\geq0$, the result equals
$\mathrm{signed}(r)+\mathrm{signed}(d)$ and that sum lies in the signed range.
A nonnegative offset cannot underflow; overflow above the signed maximum would
produce a negative word. A Boolean profile certificate adds positivity and a
cap. Loaded/indexed receipt corollaries retain the actual memory-read witness
while deriving this mathematical bound from the cached profile. These services
license no new load and add no raw-header no-overflow assumption to the
compiler. The existing source factory already handles literal word offsets;
the new \code{+1} source matrix exercises that path. This logical service is
distinct from a new Clight expression encoder or runtime-check installation.

A separate Clight library supplies a memory guarantee that permits aliasing.
If a \code{Mint32} observation holds word $w$, successful \code{Mint32} stores
of that same word preserve the observation, including stores to the observed
cell. Successful accesses supply the alignment facts that exclude partial
overlap at different addresses. A static checker recognizes typed constant-word
bodies and proves this guarantee from their actual Clight execution. It rejects
general field assignments, whose lvalues may be bitfields. This is a fixed-address
memory guarantee: pointer-binding frames, read licensing, source progress, and
model correspondence remain separate obligations.

For the supported nested source, a successor producer connects this guarantee
to the cached model. It reuses the existing source frames and capture receipts,
whose domain is silent normal source completion. A control checker classifies
actual loop control and derives header preservation for each
complete literal subloop. After the existing safe captures and numeric gates,
it compares each cached bound with the computed image of $w$ under its header
offset. Machine addition cancellation establishes that both raw headers equal
$w$. The producer then reuses the nested cached-source transport and canonical
model bridge. The emitted Clight check performs at most two cache comparisons,
preserves memory, and supplies the model-entry relation to its actual exit.
This residual check introduces no header loads or pointer comparisons.
The successor compiler statically proposes a literal store word and checks
the whole typed BODY before using it. After safe capture and numeric checks,
the two comparisons can accept stability directly; otherwise it executes the
original scan. Unsupported bodies retain the original guard. The existing
alias-only check still follows stability acceptance.

To generate only one fallback scan, the current lowering combines the two
Boolean comparisons with eager int32 bitwise AND. A language lemma requires
both operands to be defined Boolean words; the domain supplies this from the
already initialized caches. Refusal leaves the scan entry unchanged. This
lowering is unsuitable when the second check's reads still depend on the first.

A successor condition producer also supports loop-invariant affine int32
store values computed from entry parameters. For example, a fill body stores
\code{(alpha+beta)+1} throughout the nest. The language checker certifies that
every store writes that expression and that control assignments preserve all
its temporary inputs. The domain checks that those inputs belong to the
package's parameters. Their definedness follows from the existing preparation
receipt, ultimately justified by the reached original source body. The new
comparison runs after the same capture and numeric gates; inactive paths do
not require evaluating the value expression.

The emitted check compares both caches with the computed word plus their
respective header offsets. Its actual Clight evaluation, Boolean result, and
model-entry frame are proved. Equality establishes observation preservation
even when stores alias the headers. For \code{alpha=beta=INT\_MIN}, the example
expression wraps to word one; two raw headers equal to one still yield positive
counts of two. The value expression uses modular semantics, while control and
address conditions remain separate. Literal bodies retain their established
lowering; unsupported or unequal values retain the stability scan.

The new guard certificate satisfies the existing candidate presumption and
entry relation. The compact candidate, dependence checker, minimal kernel,
and language installation host are reused, yielding another actual
Csem-to-Asm compiler entry. The source descriptor supplies no additional
value-definedness, effect, or execution callback. This is a supported
condition service, rather than arbitrary assumption extraction or a
quantitative result about author effort.

Both condition producers supply the model anchor and checked-entry frame
required by the existing candidate preservation certificate. For a constant-one BODY and two raw
headers equal to one, stores through either header alias preserve its value,
allowing loop interchange where the separation scan refused. The bounded
residual check does not establish the cost of the complete guard or
optimization profitability.

The supported services cover machine-word ranges/no-wrap, byte-level memory
separation, permissions for typed accesses, and preservation of loaded values.
These are sufficient-condition libraries with declared syntax and semantic
domains. They do not decide arbitrary propositions or infer weakest conditions
for arbitrary program pairs. For a source-derived scan, the domain implementation
still proves access coverage and the source/model bridge. The language library
supplies the physical comparison and load/store preservation lemmas.

The obligations depend on how a value is used. In the new array bodies, the
scalar \code{alpha} affects stored values only: active INT\_MAX and INT\_MIN
inputs still execute candidates with the source's signed32 modular results.
Definedness follows from the reached source leaf. Control and address ranges
remain separate modeling conditions; not every arithmetic expression requires a
no-wrap premise. This distinction belongs to the concrete source/model proof,
rather than to a generic assumption about all language arithmetic.

Condition construction must preserve partial evaluation safety. A mathematically
simpler condition can read a header or compare a pointer earlier than the source
permits. Reuse therefore requires a certificate for the reordered or simplified
check, not just Boolean equivalence on states where every expression is defined.
An additional data checker evaluates the existing numeric condition under known
root and child cache words and a zero entry row. Its sufficiency theorem
transports the result to the actual entry and obtains the existing affine math
domain. It conservatively refuses extra unknown parameters, profile violations,
and wrapped inactive counts. These fact-derivation theorems have empty assumption
sets. They do not replace the production check or its execution receipts.

The numeric stage is a first-path probe followed by parameter interval tests;
it does not scan iteration points. Per-point work comes from header-stability
and cross-array alias scans. On the single-array same-word path, the former is
skipped and the latter lowers to \code{skip}, leaving a guard whose work is
independent of iteration-domain size. This does not establish a faster complete
transformation: candidate traversal and public-exit restoration also cost work.

\paragraph{Candidate bounds.}
Prepared codegen may emit, for tile coordinate $t$, the point range
\[
 [\max(0,2t,-1),\min(n,2t+2,n+1)).
\]
The earlier affine adapter encloses this range with $[0,n)$ and retains point
membership guards, but enumerates the source extent for every tile.
A new producer proposes $[2t,2t+2)$ and retains
the source-bound guards. It also proposes removal of affine inequalities
implied by loop bounds, nonnegative coordinates or stronger parallel tests.
These proposal algorithms are untrusted: the final checker revalidates the
actual adapted Loop against the conditionally valid source. Raw and adapted
outputs remain distinct evidence; there is no separate equivalence theorem
between them. The compiler theorem for zero RMW preparation quantifies over the
proposer, so this change reuses its source factory, local contract and selected
host without a new proof module or semantic kernel change.

Unit tiles expose another representation boundary: codegen identifies a unit
axis's point coordinate with its tile coordinate and removes the separate
point loop. The old six-coordinate tiling bridge then refuses installation.
A successor producer proposes singleton point loops for partially unit tiles,
lifts bound/test/operand references through each inserted binder, and proposes
canonical point operands. The final checker validates this actual completed
candidate against the source; the structural completion algorithm is
untrusted. All-unit codegen retains three actual loops and uses the existing
mapped-candidate checker with proposed affine reindex data. No-unit codegen
retains the prior six-loop path. Raw, completed and adapted outputs remain
separate artifacts, with no raw-to-completed equivalence claim. This extension
uses the same compiler theorem and introduces no kernel or host change.

\paragraph{Public-exit restoration.}
The shadow-based candidate restores public counters by replaying the source's
pure control nest after its memory computation. A successor compiler replaces
that replay with five temporary assignments for the accepted uniform nested
model. Acceptance and actual source execution supply typed cache words, an
active root, and a positive child count; the checked site supplies a positive
literal component bound. Thus each level has executed, and its final counter
equals its upper bound. Empty paths retain the original source fallback.

A language lemma constructs actual execution of a counted loop whose pure body
performs an idempotent settlement, preserves that loop's header, and commutes
with its counter update. Fixed temporary patches satisfy these laws on fresh
keys. The domain instantiates the lemma at all three levels and uses the
existing source-to-shadow correspondence and quiet determinacy to establish
the exact source exit. The candidate lowering preserves the cache bindings;
the patch then restores the source's public ports from the actual checked
entry, without changing memory.

The data-only factory consumes the same site and candidate proposals. It adds
no caller-supplied exit or execution callback. Guard correctness, memory
validation, and the installation host are reused; candidate exit correspondence
is supplied by the new producer. The resulting compiler has a Csem-to-Asm
backward simulation. This is a certified candidate implementation change, not
a general loop-exit synthesizer or a simplification of the guard condition.

\paragraph{Multi-array body library.}
A checked source-body extension supports assignment lists through several
actual pointer temporaries with a shared runtime tensor layout. Its prototype
uses \code{a[q]=b[q]+alpha; b[q]=a[q]+alpha}, where $q$ is the source
