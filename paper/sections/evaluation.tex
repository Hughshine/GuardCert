\section{Evaluation Plan and Established Evidence}
\label{sec:evaluation}

The evaluation distinguishes semantic proof, compilation, execution validation,
and cost. A successful native test is not a universal correctness proof, and
proof counts are not a measure of practical optimization value.

\subsection{Experiments Needed for the Final Paper}

\paragraph{Semantic coverage.}
Classify accepted candidates, runtime refusals, and static matcher/validator
refusals. Use the same source for independent arrays, header/data aliasing,
empty outer and inner loops, overflowing offset expressions, limited readable
allocations, invalid candidate domains, and conflicting dependencies. Verify
complete arrays and public loop exits, and inspect executed store order to
distinguish a real fast path from unchanged-source compilation.

\paragraph{Condition construction.}
Compare the scan and compact sufficient conditions on a common source class.
Report accepted input domains and refused cases. Count captures, pointer
comparisons, numeric operations, and iterations separately. Existing work
counts show that loop-shaped guard code can still perform expensive repeated
comparisons; code-size reduction does not establish cheaper checking.

\paragraph{Runtime and compilation cost.}
Use the same CompCert version, target, and backend configuration for the original
and transformed programs. Measure check-only work where separable and total
execution cost, including refusal and empty paths. Report machine code size,
compile time, measurement environment, raw batches, and dispersion. Avoid
concurrent proof/build work during timing. Slowdowns and narrow acceptance are
results to explain rather than cases to remove.

\paragraph{Proof reuse.}
For multiple transformations, identify the shared kernel, language lemmas, and
domain services. List the site-specific assumptions and source/model bridges
still supplied by the author. Compare a common example against the nearest
existing interfaces before claiming reduced proof burden.

\paragraph{Dynamic-layout source and candidate services.}
Separate library proofs connect logical coordinate vectors to runtime row-major
layouts and actual CompCert pointer/load/store operations. For positive
rectangular, temporary-bound nests with one tensor assignment at the leaf, an
adapter decodes actual Horner-address Clight execution into the memory model.
The existing affine/tiling checkers and concrete lowering then produce candidate
execution with the same complete memory; restoration from original count
temporaries preserves public iterator exits. A read-only layout condition derives
dimension-read safety from original silent normal completion. Empty outer loops
refuse before reading undefined stride or RHS inputs. The volume guard checks
positivity and quotient bounds before accumulating products. Affine extrema
cover all read/write coordinates, including negative coefficients; volume
acceptance alone does not justify coverage. A condition compiler lowers these
extrema to actual signed32 checks after a runtime parameter-profile gate.
Static range analysis rejects unsupported or potentially overflowing intermediate
arithmetic; runtime inputs outside the profile refuse. Full guard acceptance
produces the coverage, bindings, and layout views consumed by the candidate
execution bridge. The audit covers 142 endpoints (31 added to the source-adapter
stage), with no added global axioms; candidate theorems inherit the existing
checker baseline. Thirteen extracted checks exercise condition synthesis,
lowering, and mathematical acceptance/refusal. Actual guard results also have
Clight execution proofs; the extracted checks do not execute generated Clight.
These library checks are separate from the successor compiler evidence below.

A checked factory now binds data proposals to actual input ASTs and produces
the static source, parameter-use, and namespace certificates. A language lemma
transports frontend skip-wrapped bodies to the modeled source without changing

scope, and typed private resources. The resulting compiler has a Csem-to-Asm
