\section{Evaluation Plan and Established Evidence}
\label{sec:evaluation}

The evaluation distinguishes semantic proof, compilation, execution validation,
and cost. A successful native test is not a universal correctness proof, and
proof counts are not a measure of practical optimization value.

\subsection{Current Artifact Evidence}

For the loaded-root-with-offset compiler, the existing report records six
configurations and 708 full assembly calls. Separate path probes record 236
Clight calls and 21 probes of unmodified assembly. These cover candidate
acceptance and fallback, changing bounds through aliases, empty paths,
multi-array bodies, and repeated rewrites. The reports are bound to their
compiler/source digests; these are prior execution results, not a new matrix run
for this manuscript.

The earlier Figure~2 coverage report records sixteen unchanged-source calls;
it remains a fixed record, not an optimization-success count. The new frontend
closure covers 20 endpoints: 17 language results, one domain result, and two
fixtures, with 569 required dependencies and 1,104 source digests. It binds the
parent nested compiler closure, whose 25 endpoints connect original-source
checking, canonical execution, alias/candidate validation, kernel preservation,
and installation. The kernel is unchanged; the new compiler retains the same
42-global assumption set, with no additional global axiom.

The new extracted frontend compiler was run on the same adapted C source.
Six configurations---disabled, identity, interchange, $2\times3$ tiling, wrong
reindexing, and invalid domain---give 48 complete assembly calls. A further 27
calls use a harness with one additional input and unchanged kernel/context
prefix. All 75 calls compare all 2,048 output words, both headers, and public
counter exits against a GCC wrapping-arithmetic reference and an independent
source-word model. Separate instrumented Clight runs give sixteen dispatch
observations: two fast and six fallback calls for each reordered configuration.
These Clight observations are not assembly-path evidence.

Six debugger probes observe unmodified assembly. Three watch selected output
locations and distinguish their write order for one independent-array input
(Table~\ref{tab:nested-order}); the
other three check first-header or second-header-region alias fallback. The
second-header-region probe excludes a write that the cached iteration domain
would have made. Public exits and full outputs match source behavior. Probe
runs are separate from the 75-call assembly matrix. Exact commands, source and
compiler bindings, report hashes, and historical stages are in the evidence map.

The identity configuration uses 528 function bytes. Code size is an observation
of the current generated programs, not a timing or profitability result.

A separate coverage matrix uses seven functions and 119 inputs at the same
frontend entry. Six configurations give 714 full assembly calls, each comparing
6,144 words in array A, 2,048 each in B and C, two headers, three public counters,
and two context markers. It covers multi-array reads/writes, actual dependence,
same-allocation slices, nonzero entry counters, conditionally defined body
scalars, body-value wrap, repeated sites, and surrounding control. Two additional
assembly calls execute deliberately unguarded incorrect variants and confirm the
dependence counterexamples; they are separate from the successful matrix.

Three instrumented Clight configurations give 357 calls. Identity records
53 fast and 81 refusal dispatches; interchange and tiling each record 47 and 71.
There are 370 dispatches across those calls because repeated sites can execute
twice, whereas static rejection and context skip execute no select. Ten separate
assembly probes observe selected stores: independent arrays and disjoint slices
use candidate order, aliased data uses source order, repeated sites each use
candidate order, and context markers distinguish pre-loop return from post-loop
return. These are additional behavioral checks under the existing compiler
theorem, not new proof endpoints or generality inferred from call counts.
The multi-array function grows from 211 bytes to 1,579 for interchange and 1,682
for tiling, reinforcing the need to measure check work and total cost separately.

The one-column profile adds 238 complete assembly calls and 238 separate Clight
calls across interchange and tiling. All seven functions install candidates,
including the chain; each configuration observes 16 fast and 118 refusal
dispatches. The three-row, one-column chain executes fast, and its wider-domain
counterexample falls back. The default matrix also tests effective root/child
count five: the profile's exclusive upper bound rejects those inputs. No
additional assembly debugger probe is claimed for the tighter profile.

The current pipeline also passes a source-only reproduction at a fixed commit.
It exports 1,853 committed files into a new tree with no project build outputs,
restores checksum-pinned dependencies, rebuilds the target CompCert proof and
585 GuardCert/PolCert dependencies, and queries twenty endpoints independently
of historical reports. The compiler retains the same 42-global assumption set;
the kernel is closed. The new tree repeats 1,027 successful complete assembly
calls, two separate dependence counterexamples, 611 Clight calls, and sixteen
selected-store assembly probes. These totals repeat the existing matrices;
they establish rebuildability rather than broader source coverage or binary
identity. The installed pinned toolchain is reused. A first attempt exposed
missing audit-baseline build roots; after repair, the complete run started from
another empty tree.

The separate constant-word library has seven audited endpoints. Its syntax
checker soundness theorem is closed; the execution and observation theorems use
only the queried memory/Clight baseline, whose union has six assumptions.
No new runtime guard, acceptance result, or cost measurement is attributed to
these language lemmas.

The new producer has 22 audited endpoints across 508 required dependencies.
Its endpoints use only the six assumptions of the independently queried memory
and Clight baseline. The kernel remains closed. A typed indexed constant-store
instance passes both the existing source/model package
and the new BODY checker. Further fixtures establish actual check acceptance,
refusal, and skipping an undefined child cache after the first comparison
refuses. The producer proves cached-model execution and the check-exit frame;
the successor compiler supplies the installation and execution evidence below.

The same-word compiler has an independent 19-endpoint audit across 597 required
dependencies and 896 source digests. Its kernel is closed; the compiler retains
the independently queried 42-global baseline. The extracted entry uses the same
source/candidate proposal format and the existing candidate and host proofs.
Seven functions and 127 inputs give 762 complete assembly calls across six
configurations and 381 separate Clight dispatch calls across three. Full arrays,
headers, public counters, and context markers match the source-word model.

A digest-checked prior compiler runs the same new source in 127 further assembly
calls and 127 Clight dispatch calls. Interchange fast dispatches increase from
49 to 51, and refusals decrease from 77 to 75, without losing prior acceptance
in this matrix. Both new inputs have constant-one stores and raw headers equal
to one; the headers overlap output at offsets zero and five. Four probes of
unmodified assembly distinguish source write order $(4,9,80)$ from interchange
order $(4,80,9)$ for those two layouts, with public exits $(2,2,5)$ in all runs.
The small domain's tiling order is not distinguished by these probes.

Twenty additional instrumented Clight calls compare stability-check work.
For independent headers equal to one, the old scan makes 40 header-address
comparisons; the new path makes none and evaluates two cache equalities. The
two same-word alias cases replace 10 and 20 address comparisons, respectively,
with two cache equalities. Other tested inputs retain scan work and add one or
two equalities. These counts exclude other guard stages and are not assembly
instruction counts. The complete interchange function grows from 613 to 762
bytes: that stage's lowering duplicates the fallback scan. Timing and
profitability remain unmeasured.

The current single-scan lowering has a separate 23-endpoint audit across 598
dependencies and 897 source digests, with the same compiler baseline and closed
kernel. It repeats the 762-call matrix and 381 Clight calls with unchanged
acceptance. Identity, interchange, and tiling functions shrink from
$(728,762,867)$ to $(611,644,755)$ bytes. Both cache comparisons are now evaluated
when the shortcut is reached; this can add one comparison on former first-test
refusals and is not a universal runtime improvement.

For literal stores of 15 and a profile permitting counts up to 16, fifteen
inputs give sixty new assembly calls, fifteen prior-compiler calls, and
forty-five Clight dispatch calls. Each diagnostic configuration observes six
fast and nine refusal entries. The inputs include header aliases that grow the
original domain, empty paths with unreadable body inputs, nonzero entry rows,
and legal source iterations outside the candidate profile. The reference model
rereads headers after each body. Nine probes of unmodified assembly cover
independent headers and two header aliases: source order $(15,80,160)$,
interchange order $(80,160,15)$, and tiling order $(80,15,160)$, all with public
exits $(16,16,5)$. Fourteen diagnostic Clight calls show that an independent
$16\times16\times5$ same-word input replaces 2,560 stability address comparisons
with two cache comparisons. Other inputs retain scan work. Numeric checks still
precede this shortcut; complete guard cost remains to be measured.

\subsection{Experiments Needed for the Final Paper}

\paragraph{Semantic coverage.}
Classify accepted candidates, runtime refusals, and static matcher/validator
refusals. Use the same source for independent arrays, header/data aliasing,
empty outer and inner loops, overflowing offset expressions, limited readable
allocations, invalid candidate domains, and conflicting dependencies. Verify
complete arrays and public loop exits, and inspect executed store order to
distinguish a real fast path from unchanged-source compilation.

\paragraph{Condition construction.}
Compare the scan and compact sufficient conditions on a common source class.
Report accepted input domains and refused cases. Count captures, pointer
comparisons, numeric operations, and iterations separately. Existing work
counts show that loop-shaped guard code can still perform expensive repeated
comparisons; code-size reduction does not establish cheaper checking.

\paragraph{Runtime and compilation cost.}
Use the same CompCert version, target, and backend configuration for the original
and transformed programs. Measure check-only work where separable and total
execution cost, including refusal and empty paths. Report machine code size,
compile time, measurement environment, raw batches, and dispersion. Avoid
concurrent proof/build work during timing. Slowdowns and narrow acceptance are
results to explain rather than cases to remove.

\paragraph{Proof reuse.}
For multiple transformations, identify the shared kernel, language lemmas, and
domain services. List the site-specific assumptions and source/model bridges
still supplied by the author. Compare a common example against the nearest
existing interfaces before claiming reduced proof burden.

\pending{No timing, speedup, final acceptance fraction, or comparative author
effort has been measured for this manuscript. Extend the supported source class
beyond these loaded-header templates, and
measure compact conditions and author obligations on common examples. Dynamic
layout and delinearization of the full original BT kernel remain uncovered.}
