\section{Evaluation Plan and Established Evidence}
\label{sec:evaluation}

The evaluation distinguishes semantic proof, compilation, execution validation,
and cost. A successful native test is not a universal correctness proof, and
proof counts are not a measure of practical optimization value.

\subsection{Current Artifact Evidence}

For the loaded-root-with-offset compiler, the existing report records six
configurations and 708 full assembly calls. Separate path probes record 236
Clight calls and 21 probes of unmodified assembly. These cover candidate
acceptance and fallback, changing bounds through aliases, empty paths,
multi-array bodies, and repeated rewrites. The reports are bound to their
compiler/source digests; these are prior execution results, not a new matrix run
for this manuscript.

The ordered nested-header stage audits 48 language/domain/fixture endpoints
and preserves the loaded-offset compiler binding. It supplies no new extracted
compiler or native optimizer result. The adapted Figure~2 coverage probe records
16 calls through unchanged-source compilation; it is explicitly not an
optimization-success count. Detailed commands and hashes are kept in the
manuscript evidence map rather than used as research outcome metrics.

The subsequent constant-subbody joint scan audits 30 additional language,
domain, and fixture endpoints. Its execution proof uses original-source access
permissions; its acceptance proof supplies inner-prefix observation preservation.
The fixture establishes all five original stores and the actual check, including
same-allocation separation and header/data overlap. These are Clight proof
results, with no new extracted compiler, native matrix, or timing measurement.

The next stage audits 14 endpoints for the actual inner loop and its accepted-row connection to
the outer source prefix, including explicit first-refusal and empty-child
execution endpoints. These are quantified Clight execution results; no additional
array fixture or native optimizer result has been added at this stage.

The outer-scan stage audits 14 further endpoints, comprising two language
services and twelve domain results. It connects complete runtime scanning to
all-row observation preservation and actual two-cache source execution, while
retaining the existing compiler's assumption baseline. Separate first-row
refusal and empty-outer endpoints cover their actual control paths. The source
and factory input producers and optimizer installation remain pending; these
proof results add no native or timing measurements.

The full model connection audits twelve domain endpoints. It transports cached
source execution to the existing affine AST and its decoder for actual memory.
Checked leaf facts discharge the fixed loop transport. The existing compiler
assumption baseline is retained. This stage adds no extracted compiler, native
execution, or timing result.

The original-entry numeric stage audits 24 endpoints: six language services,
eleven domain results, and seven fixtures, with 565 required dependencies. It
executes ordered capture and short-circuit gates, derives used-parameter
definedness from the first original leaf, and produces scan domains and word
views on acceptance. A body-only parameter is included in a checked package;
actual empty-outer and empty-child refusals leave undefined body inputs unread.
New endpoints use at most six existing CompCert global assumptions, and the
whole-program compiler baseline remains unchanged. These producers have not
yet been assembled with the full nested physical guard and factory. This stage
adds no extracted compiler, native execution, or timing measurement.

The checked-original-site successor audits 37 endpoints: four language,
23 domain, and ten fixture results, with 584 required dependencies. Static
fixtures accept the original loaded/indexed AST and reject model substitution,
scratch-name conflicts, and a nonpositive literal subloop. Actual Clight proofs
cover an empty original source and nonzero-row refusal with every header input
undefined. The entry theorem produces current-state facts and receipts from
original-source completion; observer syntax equality separates generated code
from runtime proof witnesses. The kernel and existing compiler assumptions are
unchanged. Helper preparation, the complete physical guard, and candidate/host
installation remain to be assembled. These results add no extracted compiler,
native execution, or timing measurement.

\subsection{Experiments Needed for the Final Paper}

\paragraph{Semantic coverage.}
Classify accepted candidates, runtime refusals, and static matcher/validator
refusals. Use the same source for independent arrays, header/data aliasing,
empty outer and inner loops, overflowing offset expressions, limited readable
allocations, invalid candidate domains, and conflicting dependencies. Verify
complete arrays and public loop exits, and inspect executed store order to
distinguish a real fast path from unchanged-source compilation.

\paragraph{Condition construction.}
Compare the scan and compact sufficient conditions on a common source class.
Report accepted input domains and refused cases. Count captures, pointer
comparisons, numeric operations, and iterations separately. Existing work
counts show that loop-shaped guard code can still perform expensive repeated
comparisons; code-size reduction does not establish cheaper checking.

\paragraph{Runtime and compilation cost.}
Use the same CompCert version, target, and backend configuration for the original
and transformed programs. Measure check-only work where separable and total
execution cost, including refusal and empty paths. Report machine code size,
compile time, measurement environment, raw batches, and dispersion. Avoid
concurrent proof/build work during timing. Slowdowns and narrow acceptance are
results to explain rather than cases to remove.

\paragraph{Proof reuse.}
For multiple transformations, identify the shared kernel, language lemmas, and
domain services. List the site-specific assumptions and source/model bridges
still supplied by the author. Compare a common example against the nearest
existing interfaces before claiming reduced proof burden.
