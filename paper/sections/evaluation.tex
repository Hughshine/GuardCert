\section{Evaluation Plan and Established Evidence}
\label{sec:evaluation}

The evaluation distinguishes semantic proof, compilation, execution validation,
and cost. A successful native test is not a universal correctness proof, and
proof counts are not a measure of practical optimization value.

\paragraph{Required original-program comparison.}
The acceptance target includes all 62 cases in the
\href{https://github.com/Hughshine/PolCert/tree/ca1ae3199c816594bab9d51eb77309a0d17527aa/tests/polopt-generated}{pinned PolCert corpus}
and the \href{https://github.com/jdoerfert/CGO17_ArtifactEvaluation/tree/1b23e28261eb1c161192afa86ab996eb67d65f0c}{CGO~2017 author artifact}'s
original computations and program contexts.
Cases whose saved best route used concurrency remain in the sequential
comparison. Applicable scheduling, tiling, ISS, intra-tile scheduling,
diamond/two-level tiling and unroll/jam routes require concrete attempts;
vector annotations and actual SIMD lowering are investigated separately.
Each supported configuration must connect its checked source, guard, generated
candidate and fallback to the corresponding Csem-to-Asm theorem. Static
refusal, identity and all-fallback execution do not establish support for the
requested optimization. Comparisons must preserve numeric types and report
source adaptations and complete-call costs with comparable sequential backends.

\paragraph{First original-source attempt.}
All 62 upstream baseline C harnesses were generated at the pinned smoke tier
and compiled in disabled, scheduling and tiling modes. The initial 186 attempts
produced 180 matching native state digests. CompCert rejected the static
\code{float\_n = (double)n} initializer in \code{corcol3} and \code{pca}; GCC
accepted the original harnesses. Explicitly replacing that initializer with
the same typed literal retained the original kernel and initialization routine,
matched the original GCC digest in the adapted GCC harness, and passed the six
new compiler/native comparisons. The digest observes every modeled scalar and
array element, not all C machine state. Original types and literal dimensions
were retained, including the $10000\times10000$ fusion case.
All 124 active case/configuration pairs emitted Clight identical to disabled
and made no pipeline call. Requested optimized-case support is therefore zero
in this batch.

Original serial NPB BT Class S was also built through the same selected
compiler in all three modes. Each mode compiled all 17 C units and ran the
original $12\times12\times12$, 60-iteration program. All passed the NPB
self-check, and the ten numerical verification rows matched the GCC baseline.
Eleven top-level \code{compute\_rhs} loops were annotated; removing those
markers recovers the original source byte for byte. Their active Clight
remained unchanged, with no pipeline call. This establishes a baseline
full-context run, not BT optimization support or exhaustive state comparison.
A later script reproduction is the same coverage, not a second benchmark
result. Single-run durations are diagnostic and supply no speedup conclusion.

\subsection{Experiments Needed for the Final Paper}

\paragraph{Semantic coverage.}
Classify accepted candidates, runtime refusals, and static matcher/validator
refusals. Use the same source for independent arrays, header/data aliasing,
empty outer and inner loops, overflowing offset expressions, limited readable
allocations, invalid candidate domains, and conflicting dependencies. Verify
complete arrays and public loop exits, and inspect executed store order to
distinguish a real fast path from unchanged-source compilation.

\paragraph{Condition construction.}
Compare the scan and compact sufficient conditions on a common source class.
Report accepted input domains and refused cases. Count captures, pointer
comparisons, numeric operations, and iterations separately. Existing work
counts show that loop-shaped guard code can still perform expensive repeated
comparisons; code-size reduction does not establish cheaper checking.

\paragraph{Runtime and compilation cost.}
Use the same CompCert version, target, and backend configuration for the original
and transformed programs. Measure check-only work where separable and total
execution cost, including refusal and empty paths. Report machine code size,
compile time, measurement environment, raw batches, and dispersion. Avoid
concurrent proof/build work during timing. Slowdowns and narrow acceptance are
results to explain rather than cases to remove.

\paragraph{Proof reuse.}
For multiple transformations, identify the shared kernel, language lemmas, and
domain services. List the site-specific assumptions and source/model bridges
still supplied by the author. Compare a common example against the nearest
existing interfaces before claiming reduced proof burden.
