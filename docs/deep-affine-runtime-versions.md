同一个源循环可以安装多个经过验证的运行时版本。入口 `AffineNestRuntimeVersions.compile_guardcert_versions` 对有限的范围提案列表逐轮检查当前 Clight 程序，并用已有片段上下文变换安装每轮结果。后续一轮可以在前一版本保留的源回退分支内再安装 guard；检查与候选语法均经过原有验证器。

`affine_version_stages_correct` 对这个有限变换链组合 Clight forward simulation。每轮重新计算当前程序的 temporary 集合，分配新的私有池，并检查所有当前源片段。`compile_guardcert_versions_correct` 在最后加入已有矩形内存服务、标量 rewrite 与 CompCert 后端，得到完整 Csem→Asm backward simulation。这个入口仍然进行 AOT 编译，不在运行时编译代码。

默认 native 提案先使用既有的较宽外层范围，再使用 `start=0,n=1` 的单外层迭代范围；后者把几何参数范围提议为 `[-12,12]`。范围数字是不受信任的策略，源域、候选依赖、地址与机器范围检查决定能否安装。单迭代并不能单独证明循环分裂正确；测试保留未来点读取在内层参数过大时的反例。

两个 profile 的可接受集合不同：第一份允许多个外层迭代，但内层参数限制较小；第二份可以接受某些更大的内层参数。运行时若第一份 guard 拒绝，会求值下一份检查，最后才执行原片段。每份 guard 自身安全、保持公开入口状态，并单独证明其接受时的变换；多个版本不合成一个未经验证的语义条件。

`GUARDCERT_AFFINE_CONDITION_SEARCH=disabled` 仅保留第一轮。`GUARDCERT_AFFINE_VERSION_BOUND_LOW/HIGH` 可提出第二轮几何参数的上下界，默认上界 13 为开区间端点。不合适的配置仍由检查器拒绝；没有最弱条件或最大覆盖保证。

这一入口在整个当前程序上重新扫描并安装片段，因此其正确性保证是逐阶段程序仿真。当前 native 策略与测试使用同一个外部候选在多个范围下重验；后续遍历也可能遇到前一轮生成的其他片段。它尚未提供只改写指定回退叶的定位算法或成本定理。

构建与复现：

```sh
make affine-nest-prototype-proof
make guardcert-versions-compiler
make native-affine-nest-runtime-versions
```

提取出的入口使用 `build/compcert-guardcert-versions/ccomp`。测试将实际源请求导出为数据，用现有外部工具提出 identity、循环分裂、反向分裂及错误映射，再按源身份匹配到各轮范围提案。全部候选和配置仍经验证器复核。

测试同时包含 `start=0,n=1,m=12` 的第二版本成功见证，以及 `m=16` 时前向循环分裂改变完整数组结果的反例。后者刻意扩大范围并请求候选，检查器仍须拒绝。各调用比较全数组和公开游标；独立的 Clight 插桩会记录每份 guard 的成功、拒绝与最终源执行，而不是仅统计程序输出相同。
