# 从候选验证失败合成内层宽度条件

范围限制接口只消费具体源体提供的性质。`memory_parametric_body_restrict` 保留源语句、实际数组描述、指令、单点执行与登记表证明，将源体模型已有的外层和内层范围缩小。它通过范围包含关系搬运源解码和单点对应，不分析语句、不解释地址、不引入新的语义假设。

`memory_parametric_package_restrict` 保留真实源 AST、控制变量和仿射内层边界，只收紧供 guard 与 validator 使用的有限域。`check_memory_parametric_package_restriction` 独立检查新布局有效和新域包含于原域。范围限制不能改变实际数组访问布局，也不能被当作源代码已经执行了较小循环。

`check_memory_parametric_with_widths` 先试原描述器；失败后通过收紧内层宽度的证书包重新调用候选检查服务。统一编译器目前只尝试额外的宽度上限 1，各次仍保留外层次数搜索 `8,4,3,2,1`。每一次都必须重新通过实际域、依赖、生成代码和机器边界检查；不是仅仅插入一个未证明的条件。统一的服务正确性定理组合各次成功结果。

例如每个点执行：

```c
b[20*i+j] = a[17*j+i];
c[24*i+j+1] = b[20*i+j];
c[24*i+j] = c[24*i+j+1];
b[20*i+j] = b[20*i+j+1];
```

当内层宽度是 `m-p`，不加条件做循环分裂在 `n=1,m=2,p=0` 时会把 `b[0]` 从源结果 7 改成 52。宽度上限 1 则允许多个外层迭代安全分裂。框架从候选验证失败到新域再验证，生成实际宽度检查；宽度 2 回退到原循环。

测试输入是 [完整 C 程序](../examples/native_memory_conditioned_width.c)，独立模型与 GCC 已核对 774 行完整数组、参数和计数器输出。测试入口是 `make native-memory-conditioned-width`。额外搜索不声称得到最大允许域或任意关系前提；当前子集及枚举范围明确且有限。

搜索保留第一个验证成功的结果。原描述器若已通过较窄的外层次数条件，不再尝试额外内层宽度；交换等候选因此可能保留外层上限 1。只有原来的完整外层搜索均失败，才进入额外宽度搜索。本阶段不声称合并各个允许域或生成最弱条件。

全量审计重新编译了 154 个内存适配模块和七个 lowering 模块，完整编译器的假设集合仍精确等于原有 CompCert／validator 的 42 项并集。提取编译器 SHA-256 为 `3a75482f1cfcd0da7f38cdafe01c79c165bdbbab61f088383d69dce3c9deb306`。七组完整汇编配置的 774 行输出逐一匹配 GCC 与独立模型：identity、interchange、fission、二维 2×3 tiling 接受两个支持的函数；维数错误、资源耗尽与错误证书保留源程序。

四组分支诊断执行经插桩的 Clight 打印代码：确认每个支持函数的快路与回退，分裂在 `n=4,m=1,p=0` 时进入快路，在上述宽度 2 反例时回退。分裂的外层 guard 上限为 24；交换与 2×3 分块为 1，反映上述首次成功搜索策略。诊断并非汇编插桩；完整汇编输出另由主测试核对。证据位于 `build/native-memory-conditioned-width/report.json`、`branch-report.json` 和对应 `build/memory-conditioned-width-*.log`。

此前多读取整数计算套件的 14 组汇编配置及五组分支诊断在这个编译器上也通过。更复杂的 `2*i+m-p` 复制链仍拒绝分裂，即便增加 FM 行数预算也未接受；这只是当前可接受条件的限制，测试中的正确结果来自源回退，不作为优化成功。
