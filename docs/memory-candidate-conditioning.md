# 从多面体候选搜索安全运行条件

本阶段增加有限的候选条件搜索，复用实际源语义、前提编码、独立域与依赖检查、机器 lowering 和完整程序宿主。它与原先“规则作者已给出条件”的入口不同：候选在默认参数域失败后，编译器尝试更小的输入域，并重新验证同一个候选。

## 使用接口

`check_memory_parametric_region_mapped live pool describe bounder propose source` 接收实际源包解析器、参数区间生成器和不受信任的候选提议器。`bounder` 可以由工具提供；只有在该区间上的语义域、访问依赖、运行时前提编码及机器 lowering 均通过时，才返回有 `projected_region_contract` 保证的带检查片段。任意区间并不会被直接当成正确性证据。

默认策略先使用源布局生成的参数区间；失败后依次尝试把外层执行次数的上界限制为 8、4、3、2、1，同时保留其他参数区间。每次接受都由同一个已验证检查器核对。区间本身由运行时检查消费，超出范围进入原循环。搜索是有限策略，不计算任意程序的最弱条件，也不声称找到最大成立域。

直接候选、实际调度生成和二维 tiling 都支持这个入口。调度生成仍在默认源域上运行；缩小条件后重用生成出的候选并重新验证，避免重新生成时删除迭代维度。无效维度、非法机器系数、耗尽的证明搜索或错误证书不会因区间被建议就跳过检查。

## 语言实例提供什么

`memory_parametric_body_model` 为实际源语言提供五类证据：循环体控制与 temporary 写入范围；源体到单点执行关系的解码；首个实际执行点提供的对象登记与地址有效性；物理单点执行与内存指令列表的对应；这些性质适用的行列范围。地址公式和具体 load/store 语法留在语言实例中。

`memory_parametric_body_source_decode`、`memory_parametric_body_source_domain` 和 `memory_parametric_body_candidate_rule` 从这些证据构造源循环对应、guard 安全及候选执行。在 `4adeeca` 中有两个已实例化并由完整编译器消费的模型：同布局的读写混合列表，以及独立读写布局的一条复制，后者包含同一对象的不同步长访问。这些模型不是未证明的占位接口。

`memory_parametric_region_package` 将模型、完整源 AST、稳定参数和控制变量证书交给通用检查器。统一 C→Asm 编译入口实际调用上述服务，其结果继续由 `compile_memory_unified_regions_correct` 提升到完整 Csem→Asm 正确性。核心 guarded transformation 框架的语言实例化原则不因此改变。

## 例子与验证边界

[同一数组布局重映射](memory-same-array-layouts.md)中的循环交换在默认域存在真实依赖反例。实际有限区间搜索为该候选生成 `N≤2` 的外层次数条件；该范围内进入快路径，已知反例输入回退。`2×3`、`4×4` 和 `17×13` 分块也生成并验证了这个保守条件。二维 tiling 使用相同条件搜索及专门的点空间证明。

`make native-memory-layout-copy` 验证实际提取编译器的完整汇编输出。另有 Clight 打印结果的分支诊断：对打印器的参数名称及一次执行循环表示作局部修正，在成功分支出口加入计数，再用 GCC 核对选择及输出。这部分是诊断，不是另一条已验证编译器；真正的证明端点与汇编输出检查另行保留。

当前条件语言由参数区间、仿射上界的安全端点条件和实际对象关系组成；不支持任意关系式条件发现、一般指针切片重叠或中途恢复。永久为假的条件在逻辑上可能安全，本接口不提供一般可满足性证明；实例的测试必须同时报告实际快分支可达与反例回退，不能只计生成了几个 guard。

本阶段（`4adeeca`）完整 Rocq 审计通过：127 个适配模块和 7 个 lowering 模块，完整编译器仍继承 42 项原有假设。使用同一个新编译器的 15 组布局配置、15 组参数化配置和 8 组外围上下文配置全部通过。四种条件化配置分别验证了两个同数组函数的实际快分支可达、已知依赖反例回退、零次执行和非零起始计数器回退；完整汇编输出另与 GCC 和独立源模型一致。
