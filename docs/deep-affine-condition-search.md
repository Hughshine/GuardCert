深层仿射候选现在可以在有限的源范围条件族中搜索。输入仍是实际 C 源片段与外部候选；每个范围提案都必须重新通过源对应、域对应、依赖保持、机器 lowering 和守卫检查。接受后生成真实 Clight 条件与原片段回退，并由 `compile_guardcert_conditions_correct` 接到完整 Csem→Asm 正确性。

例如，源程序按点执行：

```c
for (i = start; i < n; ++i)
  for (j = 0; j < i + m; ++j) {
    a[512*i + 32*j] = b[512*i + 32*j] + alpha;
    c[512*i + 32*j] = a[512*i + 32*j + 480] + beta;
  }
```

外部工具提议先完成所有 `a` 写入，再完成所有 `c` 写入。在默认范围内，这会提前覆盖源程序本应读取的旧值。检查器拒绝该候选。搜索随后尝试 `start=0, n=1` 的范围方案，并保留内层参数的窄范围及实际访问分离条件。依赖验证在这个域上通过，框架才生成守卫。超出条件的调用执行原片段。

仅有一次外层迭代不保证安全：`m=40` 时，偏移 `480` 可以指向同一外层迭代中后面的内层点。测试保留此反例。另一个候选反向执行本轮 producer/consumer，即使一次外层迭代也会读取错误的旧值；搜索仍拒绝它。

抽象接口是 `first_checked_candidate check proposals`。它只要求每个检查成功的结果满足同一个契约，不知道具体语言或内存语义。`first_checked_candidate_sound` 没有全局假设。实际语言实例 `check_conditioned_region` 为每个提案构造原有 `projected_region_contract`。现有源条件与检查编码证明承担条件定义性、检查安全、真假分支和公开状态对应，宿主证明承担完整程序组合。

默认提案族有两个成员：原范围策略、单次外层迭代策略。编译时选择首个验证通过的方案；运行时只有被选方案的守卫与原程序回退。它不把多个方案的接受域求并，不保证找到最弱条件、最大成立域或可满足条件。策略与外部候选均不受信任；测试说明实例中的接受分支确实可达。

在仓库工具链内运行：

```sh
make affine-nest-prototype-proof
make guardcert-conditioned-compiler
make native-affine-nest-condition-search
```

提取入口位于 `build/compcert-guardcert-conditioned/ccomp`。原来的 `guardcert-compiler` 入口保留原单方案行为。`GUARDCERT_AFFINE_CONDITION_SEARCH=disabled` 可在新入口中关闭窄范围搜索，便于同源对照。

外部候选可使用 `(source DIGEST candidate)` 在不同范围提案间匹配同一实际源 IR、参数和指令；生成工具的 `--source-match` 选择这种格式。摘要只用于寻找候选，不是正确性证据。候选、范围和坐标／站点证据仍逐次被已验证检查器检查。精确包含范围的 `(request DIGEST candidate)` 接口继续可用。

七组配置各执行 612 次，共 4,284 次真实 CompCert 汇编调用，逐数组和公开变量比较一致。宽范围正向分裂拒绝未来读取函数；开启搜索后该函数安装条件版本。反向分裂仍拒绝本轮依赖，错误映射和资源耗尽保留源片段。独立 GCC 执行的实际 Clight 插桩共 2,142 次，观察到 460 次候选、1,682 次回退。其中 12 次安全的单次外层迭代进入新增候选，112 次更宽的未来读取输入回退，数值范围成立但实际地址重叠的输入也回退。

`native_guardcert_conditioned.py` 另外用同一个搜索编译器运行六组标量／矩形／深层服务配置。该回归关闭窄范围搜索，以保持原测试对各候选安装范围的断言；候选条件搜索本身由前述独立 fixture 验证。此回归完成 5,928 次真实汇编调用和 3,039 次 Clight 诊断。因此本阶段搜索编译器有 10,212 次汇编调用和 5,181 次独立诊断，两种证据分别记录。它们不能与另一个编译器版本的历史次数混作同一版本证据。
