# 有符号循环和地址窗口

本阶段扩展实际指针片段的入口：根循环起点、稳定地址参数和逻辑数组下标可以为负数。它仍使用实际源 AST 和原有完整程序编译入口，候选提案器不受信任。

```text
源入口比较和逐层执行信息
  → 有符号根范围、正的各轴上界、地址参数区间
  → 静态证明本片段单个指针窗口内的不同单元分离
  → 已检查候选、实际机器代码和源公共出口恢复
```

`p[i+u]` 可以访问指针基址之前的单元。这里的窗口约束逻辑下标，不宣称指针拥有整段分配。源的正常执行提供实际访问点的权限；候选的点对应和依赖证明保证它使用对应的源单元。

## 接口与证明

`interval_window_box_exact` 给出整数区间 box 中仿射访问落入窗口的精确数学判定。`window_compute_check` 将它用于已支持的地址和 RHS 语法，独立检查完整实际源。地址参数区间与 RHS signed32 范围分别处理。

`window_region_package` 保存源、各轴上界、根起点下界、参数区间、逻辑窗口和静态证书。`make_window_region_package` 返回的包带有检查器正确性证明。`window_started_package` 再绑定实际根游标、上界和内层重置语法。

`window_package_header_domain` 从真实源执行推出检查代码所需的类型。短路顺序首先检查根是否活跃及各轴上界，再检查地址参数。空域可以在读取未初始化参数之前拒绝。`window_package_header_sound` 和实际 Clight 编码证明把布尔结果对应到声明的区间前提。

`window_package_validator_within` 和 `window_package_encoder_within` 分别提供依赖验证器和机器 lowerer 使用的范围。候选服务基于实际源循环 IR 验证直接或调度生成的候选。自动调度生成器只携带可安全表示的循环次数约束，验证器和 lowerer 保留完整范围义务。

`window_single_candidate_rule` 合成实际源对应、单指针受限状态、依赖验证、机器执行和公共出口恢复。它接到同一个 `compile_memory_unified_regions_correct` 的 `Csem → Asm` 定理。

## 使用与当前范围

```text
(interval (per-axis (schedule ((coordinate 1) (coordinate 0) ordinal) ((swap 0)))))
(interval (per-axis (schedule ((negative-coordinate 0) ordinal) ((reflect 0)))))
```

统一提案请求的 `request_signed_window` 暴露所选根下界、地址参数区间和逻辑窗口；`request_source_loop` 提供实际源循环 IR。提案器可以使用这些信息生成候选，正确性不依赖其选择。

原生入口尝试有限静态 profiles，独立检查每个 profile 和候选，采用第一个成功者。当前半径为 64、16、8、4、1，逻辑窗口为 `[-1024,1024)`，各轴上界独立搜索。它没有合成最弱条件，也不是同时执行多个运行时版本。

当前支持一个真实指针、负数根起点、负偏移及负地址参数。根上界仍要求为正数，内层循环仍由源 AST 重置为零。多指针 signed 快路、signed 分块、更一般深层仿射域及版本族组合尚未接入；不支持的提案保留源片段。

当前单指针路线静态证明 `4 × 窗口宽度 ≤ Ptrofs.modulus` 和不同逻辑单元的地址分离，不生成运行时指针比较。这个事实不替代循环依赖检查：例如邻居读取的循环仍可能禁止反向调度。

## 实际例子

测试内核的一段源循环为：

```c
for (i = start; i < n; i++)
  for (j = 0; j < m; j++)
    p[16*i+j+u] = alpha*i + beta*j;
```

交换候选的一组实际生成条件为 `i < n`、`-16 <= i <= 62`、`0 < n <= 63`、`0 < m <= 16` 和 `-16 <= u <= 16`，按这个短路顺序执行。`i` 是当前片段入口游标，已经执行源初始化。条件通过后，候选交换两个循环，私有计数器保留入口快照，退出恢复 `i=n`、`j=m`。例如 `start=-2,n=3,m=2,u=-1` 实际进入候选，包含负逻辑下标；条件不通过则执行原片段。

条件是经过验证的充分条件，不是最弱条件。实际访问范围与指针权限来自源对应，指令顺序合法性来自依赖证书，RHS 采用实际 CompCert 整数语义。调用者可以给 `p` 一个缓冲区内部的指针，测试使用完整缓冲区中心作为基址。
