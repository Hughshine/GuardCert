# 不同布局的读写操作序列

统一完整 C 编译器现在识别带参数化仿射内层上界的操作序列，各条操作使用自己的数组长度和步长。复制、纯写、原地更新、行首读取及已有同布局跨数组计算可以在同一个循环体组合；同一数组可以被多条操作以不同步长访问。检查器验证整个列表的真实依赖，而不是假定各条语句独立。

## 实际源与候选

例如，三个实际数组分别按 22、17、15 的步长访问：

```c
for (; i < n; ++i) {
  k = 2 * i + m - p;
  for (j = 0; j < k; ++j) {
    a[i * 22 + j] = i * 37 + j + 7;
    b[i * 17 + j] = a[i * 22 + j];
    c[i * 15 + j] = b[i * 17 + j];
    b[i * 17 + j] = b[i * 17 + j] + (i * 11 + j + 19);
  }
}
```

每条赋值都生成实际读写访问函数。保守公共域约束可执行的行数与行宽，但源、指令与候选继续使用各自的真实步长，不将数组重解释为公共布局。交换、分裂、平移、剪切和二维分块仍由外部候选描述提出；生成代码随后接受独立域、依赖、机器边界和运行时条件检查。失败时保留原循环。

## 具体证明接口

`memory_layout_operation` 是语言实例的操作表示。`MemoryLayoutNamed` 复用已有纯写、更新和读取语义，`MemoryLayoutCopy` 分别携带读写布局。每条操作提供真实 Clight 语句、对象请求、内存指令和物理执行关系。

`memory_layout_operation_clight_inverse` 将实际赋值执行解码为物理 load/store；`memory_layout_operation_registry_execution` 证明它与内存指令在同一个 `Mem` 上对应。`memory_layout_sequence_point_execution` 顺序组合任意有限列表，保留所有中间内存及操作次序。读写数组的基址有效性由首个实际执行点得到，并经先前 store 的权限保持证明向入口传递。

`memory_unique_descriptors` 按实际对象标识去重。`memory_descriptors_cover_check` 核对每个请求的变量和对象长度；同一对象的不同步长保留为不同访问函数，并共享一个对象登记项。请求长度不一致则拒绝。真实对象登记及非别名检查继续使用既有后端，而不是把标识符不同直接当成物理不相交。

`memory_layout_body_model` 具体实例化通用 `memory_parametric_body_model` 的全部语义义务。`describe_memory_layout_region` 检查完整源 AST、公开循环变量、稳定参数、各自布局和公共域后，向同一个通用候选检查器返回有证明的源包。这些模块由 `GuardMemoryUnifiedCompiler` 的实际入口调用，并继承 `compile_memory_unified_regions_correct` 的完整 Csem→Asm 端点。

## 验证与范围

复现目标为 `make native-memory-layout-sequence`。输入是 [实际 C 测试程序](../examples/native_memory_layout_sequence.c)，包括不同布局复制链、列表中的更新、全局数组、外围重复循环，以及同一对象的两种重映射。独立模型按源语句次序逐步执行，检查完整数组及公开 `i/j/k/m/p`。

本阶段全量 Rocq 审计通过：134 个适配模块和 7 个 lowering 模块；完整编译器仍为 CompCert 与 validator 的原有 42 项假设并集，没有新增公理。新编译器的 14 组配置逐组核对 5,844 行完整汇编程序输出，均与 GCC 和独立源模型一致。正确的仿射候选与四组分块在六个受支持函数中均生成实际快路径；错误映射、错误维度、机器系数溢出、证明搜索资源耗尽和错误证书均回退。

另有五组 Clight 打印结果的分支诊断，逐组验证六个函数实际命中快分支（外围重复循环命中两次）、零次执行和非零起点回退，并验证同数组函数超出缩小条件域时回退。诊断修正打印器的参数名与一次执行循环表示后以 GCC 运行；它不代替上述已验证编译器及汇编测试。交换和分块为两种同数组列表分别选择 `N≤3`、`N≤4`；分裂为反向重映射列表选择 `N≤1`。独立执行给出了交换、分裂及两种分块的真实依赖反例；没有为 `17×13` 配置声称存在已找到的反例，也没有声称所选区间最大。

同一个新编译器还通过前阶段的 15 组参数化上界、8 组外围上下文和 15 组独立布局复制回归。报告位于 `build/native-memory-layout-sequence/report.json`、`branch-report.json` 和相应回归目录，均核对编译器内容哈希。此前有限候选条件搜索阶段的 127 个适配模块、7 个 lowering 模块及 38 组完整程序配置，对应提交 `4adeeca`，见[该阶段记录](memory-candidate-conditioning.md)。

当前仍要求两层标准计数循环、零起始快路径、规范的 `i * stride + j` 数组下标，以及受支持的算术右侧。独立布局的复制已支持；不同布局的跨数组算术、邻居下标、一般仿射读写、多层 C 仿射域和任意指针切片还需扩展。运行时条件搜索仍是有限区间策略，不能视为最大成立域或任意前提发现。
