# GuardCert 当前交付与研究边界

当前产物是一个可提取运行的 CompCert 编译器。输入受支持的 C 循环与外部候选后，它独立检查源、候选域与依赖，生成安全的运行时前提检查、候选代码和源片段回退，并提供完整 Csem→Asm backward simulation。PolCert 是功能与证明架构参照；这里的真实 CompCert 内存、机器运算、检查代码和出口桥接采用自己的已证明实例。

通用核不解释 overflow 或指针。语言实例提供性质维度、条件构造、检查求值与状态保持、条件局部精化和公开观察运输。规则作者证明具体前提足以支持变换；候选使用者提交程序和数据，不需要给每份候选另写整程序证明。接口与使用命令见[使用说明](api-usage.md)。

顺序多面体实例已支持有限深度的规范 signed32 循环：子上界可依赖外层游标和稳定参数；可从负根进入；操作包含多个实际稳定指针的 load、乘加、重复读改写和多语句。外部候选可提出平移、skew、reflection、站点重排／fission、完整切面分区和前两轴分块及实际两层组合。新递归证据支持 `source → middle → candidate`，每段各自受检，最终复用原源的 guard、出口恢复和完整程序宿主。

实际累加例子为 `a[32*i+j] += b[32*i+k]*c[32*k+j]`。盒式和参数化 `i-k-j`、相应的交换后分块及完整分区均被接受；相应错误映射、错误第一段、错误 witness 与缺片目标被拒绝。检查失败或输入前提不成立时执行原片段。数据乘加保留 signed32 回绕，控制和地址运算另受检查。恒等、参数化、平移、分块等的行为验证与成本实验分别报告，见[累加](deep-affine-accumulation.md)、[组合](deep-affine-composition.md)和[成本](deep-affine-cost.md)。

同一完整程序入口也包含条件标量 rewrite，如 `(x*y)/y → x`：非零与乘积范围性质由实例证明，共用短路条件编译。有限条件搜索和多个运行时版本有独立的完整程序入口；搜索只保证找到的方案可靠，不保证最弱条件或最大覆盖。

2026-10-04 当前版本编译了全部 **104 个原型证明模块**，复用已审计的既有适配器，构建绑定 **715 个证明源码**。模块数与源码绑定数是不同指标。源端、区域端和完整程序端精确保持既有的六、14、42 项全局假设；没有新增全局公理。工具链锁定 CompCert v3.18、Rocq／Stdlib 9.2.0。单指针与多指针深层区域已通过 Clight 私有结果变量的语言实例调用通用有状态核心；具体条件编码、语义候选证书和完整程序宿主继续由实例提供，见[核心连接](deep-affine-core-interface.md)。

这些数字只计对应二进制相应报告的通过配置。最后一轮核心连接仅改变语言实例和两份区域证明；重新提取的三个二进制与 `9c97b9b` 保存版逐字相同，证明绑定刷新为 104 模块／715 源码。表中的运行记录保持原始报告，通过二进制一致与保存文件摘要核对复用，没有为证明改动重复计数。编译超时没有算成拒绝或通过；双切面源展开后做通用分块的两次 600 秒超时另行保存。目标完整分区的结构证据避免重新验证复制站点，已完成同样时间限制内的实际分块测试；其他复杂候选仍可能成本过高。诊断源文件现在按深层／矩形分别保存，历史共用临时文件的证据限制已明确记录。

性能实验暴露了两个问题。在一个 42 点、数据在缓存中的小内核上，三指针平方检查使 guarded 版本精简扫描后仍约慢 200 倍；同一指针的显式窗口省掉跨指针扫描后，参数化交换约为源成本的 1.45 倍；参数化分块约为 2.3 倍，盒式分块仍约为 35 倍。源码和窗口布局的汇编与上一版逐字相同，不能把其计时波动解释为扫描改进效果。五组源点数实验另确认当前检查仍按点对增长，见[扫描精简](deep-affine-scan-cost.md)。此处没有整体运行时加速结论。更低成本的真实指针检查、避免空点枚举的候选生成、公开出口恢复成本及较大域评估，仍应优先推进。

当前尚未覆盖任意 C 控制流片段、动态步长、一般非仿射地址、一般多轴、多层分块策略、并行／向量运行时或任意源／候选的关系式前提发现。Native 源识别深度和私有变量池有限，候选生成与 profile 搜索均可替换但不保证最优。完整程序定理从 CompCert Csyntax/Csem 起步，文本解析、系统汇编器、链接器与运行库另属执行边界。

文献方面，CGO 2017、COVE/cSTOKE、CoreJIT、Peek、Chamois、CompCert-loop 和 VLIM 覆盖不同近邻；guard、语义参数化和片段到整程序组合各自都不足以建立新颖性。VLIM 的 runtime guard 含义仍因全文获取限制未确认。可检验的贡献方向是可执行前提处理的具体算法、真正跨算术与内存实例的证明复用，以及检查成本与接受覆盖的改进。当前总体目标继续开放，不能把已完成的实例当作全部多面体能力达成。
