# 研究动机与范围草稿

本项目研究带前提的程序变换及其组合证明。条件可能约束算术范围、访问区间、别名、不变读取、代码身份或分支可达性；变换可能是优化、重构、快速路径或检查消除。首条实现主线要求在前提下保持或精化原行为。修复、软件更新、运行时 enforcement、数值近似和 constant-time 带来不同判断，需各自说明允许变化、状态对应或执行间观测，不能都解释为原/目标结果相等。[跨领域 survey](survey-general.md) 明确区分这些场景。

这类变换面临两个不同的问题。第一，编译期未必能确定某次执行满足前提；参数值可能到运行时才知道，静态分析也可能过于保守或成本很高。第二，数学模型中的前提不一定能直接在目标机器上求值：用于检查的算术可能回绕，参数预读取可能不安全，内存关系还依赖程序表示。[IMPACT 2012](https://acohen.gitlabpages.inria.fr/impact/impact2012/workshop_IMPACT/cuervo.pdf) 已提出版本化与检查算术的语义；[CGO 2017](https://pollylabs.org/publications/grosser-2017-Optimistic-Loop-Optimization.pdf) 系统组织了假设收集、入口条件推导、简化和运行时检查。

我们希望让这种条件化正确性通过可复用接口接入经过验证的编译器。关键对象是具有明确表达范围的 **presumption 语言**，以及把它处理为证据或可执行 condition 的 **已验证算法**。presumption 具有独立的数学语义；condition 具有机器值、检查状态和控制流语义。需要分别证明编码、入口条件推导、静态事实消解、残留检查编译和插入。运行时证据说明这次执行能否应用规则；候选本身的条件正确性仍由证明或可信 checker 保证。

“统一”不要求一个语言表达任意程序谓词。我们先选择可计算、能给出明确代码生成策略的子集：标量算术与范围、无溢出、显式区间边界和不相交，以及布尔组合。循环中的全称义务可以由独立的入口推导层转化为这类条件，但推导可靠性不能由后面的布尔代码生成定理代替。不变读取、真实指针比较和读取权限也需要各自的适配与证据。

局部变换的输出不仅是一个值，还包括可观察事件、上下文可见状态和控制出口。将其嵌入完整程序，需要入口与出口关系、外围控制流适用性以及发散时的进展保证。每个插件提交局部证明、通用框架承担上下文组合，已经由 [Peek，PLDI 2016](https://darzu.io/files/pldi2016.pdf) 和 [CompCert 块仿真框架](https://www-verimag.imag.fr/~boulme/pub/poster_OOPSLA23.pdf) 等实现；[Icing](https://cakeml.org/cav19.pdf) 也已有带前提 rewrite 接口，[CoreJIT](https://www.o1o.ch/about/assets/courir.pdf) 已证明 guard 插入与恢复。因此，这些内容构成本项目的基础，不能单独成为贡献。

候选研究问题应收紧到：同一条件规则证书能否在静态和运行时应用之间复用，以及从语义前提到真实安全检查代码的处理能否由一个可运行、已验证的算法完成。新意需要体现在明确的适用前提类、生成或验证算法、真实 IR 连接和证明负担收益。它与 CGO 2017、Chamois、CoreJIT 等仍可能重叠，详见 [研究定位](research-position.md)；现阶段不宣称这是已确认的文献空白。

第一阶段聚焦入口版本化：在片段产生效果前选择候选或原片段。实例包括无回绕条件下消除分支、条件算术取消、除法/取模特化和恒假分支删除。共享 Clight 条件树、真实内存和片段宿主随后已实现；中途去优化、浮点模式和对象表示恢复需要另外的协议证明。[框架扩展设计](framework-extension.md) 将设计需求与已有能力分开。

研究结果应分别报告编码、条件合成、检查执行、局部仿真、真实 IR 上下文提升和 backend 组合的完成程度。语义核中的定理不能替代实际 CompCert pass 的正确性；运行时 guard 返回 true，也不能替代候选变换的证明。

截至 2026-10-03，Clight 分支与表达式实例，以及真实 CompCert 内存上的限定多面体源族，都已接入 `Csem → Asm` backward simulation。多面体统一入口支持动态矩形、带稳定参数的有符号仿射内层上界（如 `j<2*i+M-P`）、多个实际数组对象、跨数组读取和复制；不同长度和步长数组的复制与混合操作序列也已证明源与候选对应，并消费实际域／依赖检查来接受外部仿射候选、组合坐标对应和二维分块。边界和数组非别名前提经共享条件树生成实际检查；不接受时执行源片段。源、候选、guard、公开计数器出口和外围上下文均有具体证明，并已提取编译完整 C 程序。

这仍不是任意 C 源程序的多面体编译器。更深的嵌套仿射源识别、更广仿射访问、不同布局的跨数组算术和指针切片，超出当前有限区间搜索的候选条件发现，中途恢复及其他判断族仍有缺口。条件树可以复用已证明的原语，完整抽象 DSL 的每一种语义维度也不能由此视为已支持。实际支持范围和验收差距见 [多面体接入目标](polcert-integration-target.md)、[真实内存实例](../adapters/compcert-memory/README.md)、[接入说明](compcert-integration.md) 和 [常见 rewrite](common-rewrites.md)。

[实际候选的有限区间条件搜索](memory-candidate-conditioning.md)已接入：默认域失败后，提出较小的执行次数区间，重新验证同一候选，证明检查与完整程序组合。具体语言模型提供单点执行、内存对应和 frame 证据；通用层复用源循环与候选证明。
