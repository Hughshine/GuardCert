# 多指针源循环与访问分离 guard

这条扩展允许源循环从多个稳定的 `int *` 参数读取和写入。指针可以来自不同内存块，也可以指向同一内存块中的切片。源解码允许别名；实际依赖验证器在 guard 建立的受限内存视图上验证候选，再将候选执行还原到完整 CompCert 内存。

2026-10-03：全量 Rocq 审计通过，重编译 269 个适配模块和七个 lowering 模块。完整 `compile_memory_unified_regions_correct` 仍继承 CompCert 与 VPL 的原有 42 项假设，没有新增全局公理。实际提取编译器的 11 组完整汇编配置和九组分支诊断全部通过。

## 从源访问生成检查

源仍是有限层规范矩形计数循环，支持正、负及混合系数的仿射坐标下标、稳定 RHS 标量及实际机器整数加减乘。例如：

```c
for (; i < n; ++i)
  for (j = 0; j < m; ++j)
    p[8*i+j] = q[8*i+j]*alpha + r[8*i+j]*beta + i*j;
```

实际检查按顺序生成，每一项通过时继续，拒绝时跳到共享回退；`memory_private_rule_sequential_sound` 复用性质框架的片段契约。`memory_compact_alias_statement_execution` 证明顺序代码与条件模型一致，避免把后续检查复制到多个接受分支。

生成器从每条语句的实际读写访问建立条目：逻辑单元、常量坐标和该坐标的执行条件。共同次数上界之内的坐标在编译时枚举；运行时先检查原有计数条件，再只比较条件成立的访问地址。例如，上界为 4 时，坐标 `(2,1)` 的访问只在 `2<n && 1<m` 下参与检查。

`memory_rectangular_selected_members` 证明条件成立的条目与实际矩形范围中的访问具有相同成员；`memory_multi_pointer_selected_footprint` 将这些成员接到真实源 Loop 的访问轨迹。`memory_multi_pointer_region_source_guard_domain` 从成功的实际 Clight 源执行推出整个检查的求值域。

源中的 `Mem.load` 和 `Mem.store` 提供已访问单元的权限与对齐。权限在循环的 store 之间保持，可以回传到入口。新插入的地址比较因此有定义；它不假定指针分配了整个逻辑窗口。空指针、未初始化的标量及小分配的未使用地址不应被额外读取。

两个不同逻辑单元只有在实际 4-byte 单元分离时才能共存于受限视图。Mint32 源访问给出对齐，实际地址不等足以推出四字节分离；这也允许同一 block 内的不重叠切片和交错访问。相同逻辑单元无需彼此分离，其内部依赖仍由依赖验证器处理。

## 编译与证明接口

| 接口 | 提供的保证 |
| --- | --- |
| `check_memory_multi_pointer_region` | 核对整个源 AST、坐标范围、访问与 RHS 编码、稳定参数及受保护的指针绑定。 |
| `memory_multi_pointer_region_guard_statement` | 从源访问生成顺序 Clight 检查；只有活动访问地址会被比较。 |
| `memory_multi_pointer_region_guard_nonalias` | 检查通过时，保留本次源访问单元的内存视图满足实际 INSTR 的 NonAlias。 |
| `memory_scalar_candidate_certificate` | 同一依赖与域验证接口，在该视图上建立候选执行；包含映射、直接调度及分块。 |
| `compile_memory_multi_pointer_buffer_loop_correct` | 每次访问使用对应的入口指针地址，生成实际 Clight 读写；保护指针绑定并保留公开临时变量。 |
| `memory_multi_pointer_candidate_rule` | 组合条件编码、候选正确性与出口恢复，形成完整程序宿主消费的片段契约。 |

源入口不要求 NonAlias。源在受限视图中的执行由访问覆盖证明给出；验证器建立候选进展；成功的候选指令只能使用这个视图中可解析的单元，因而可以回到原始完整内存执行。最终保留实际 Mem 和公开计数器出口。

## 可运行检查

`make native-memory-multi-pointer` 将运行原生汇编输出比较和独立分支诊断。测试源 `examples/native_memory_multi_pointer.c` 包含双指针复制、三指针计算、跨点依赖链、反向读取、重复上下文、零次循环中的未初始化标量以及只有两个元素的实际分配。

每组完整汇编配置执行 279 次函数调用，结果与 GCC `-O0 -fwrapv` 和独立 32-bit 模型一致。配置包括恒等、换序、逆序、直接调度、语句分离、三组分块、错误证书和资源耗尽。九组分支诊断每组执行 584 次调用，总计 5256 次，其中 3251 次进入优化路径、2005 次回退，检查实际路径选择。分支诊断执行带计数标记的 Clight 打印结果，完整汇编结果另行检查。

## 本阶段边界

检查当前要求所有不同逻辑访问单元分离，包括只读单元之间的别名，因此会拒绝一些安全的只读别名情形。检查数量也会随坐标上界增加：生成器最多保留 64 个潜在访问条目，依次尝试次数上界 `8,4,3,2,1`，不足以生成或验证候选时回退。这个资源界限不是分配长度或正确性前提。

逻辑窗口保持 1024 个单元，用于地址范围编码，不作为实际对象长度假设。深层依赖外层坐标的非矩形源域、访问下标中的稳定外部参数、更广的 tiling／ISS 和并行执行尚需后续实例化。

原生报告位于 `build/native-memory-multi-pointer/report.json` 和 `branch-report.json`。编译器 SHA256 为 `fe7a6e115a0df6e418ea038597970b532bd8e85c02d89907f922a43910aa4411`。同一编译器还通过 signed 仿射地址和稳定标量固定数组各三组、稳定标量指针全部 16 组及单指针全部 15 组配置的完整汇编回归。

本文记录有限枚举阶段的编译器及资源限制。后续[多轴活动扫描](memory-multi-axis-alias-scans.md)已在 `6180edd256…` 上重跑这套 11 组／3069 次完整汇编调用和九组／5256 次分支诊断，分别有 3302 次候选、1954 次回退；当前构建报告对应后续版本。边界诊断把 `cap+1` 放在连续轴，并检查源访问位于实际分配内，避免新共同 cap 超出旧测试缓冲区。64 条潜在条目只约束旧有限路径；新矩形扫描使用至多 32 条原始访问和私有循环。
