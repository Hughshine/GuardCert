2026-10-04 的小内核实验说明：当前深层多指针检查的成本可以超过候选计算的成本，盒式候选还会枚举许多空点。完整程序正确性已经成立，但它不证明性能收益。

实验使用已审计的统一编译器 `3e8a5e232ab2…`（测量时 103 个原型模块、714 个证明源码绑定；核心连接后为 104／715，二进制逐字相同），运行非矩形累加 `a[32*i+j] += b[32*i+k]*c[32*k+j]`，入口固定为 `start=0,n=4,m=2,p=3`，每次有 42 个源迭代点。源序、guarded 恒等、盒式交换、参数化交换、盒式和参数化分块及分区组合共八种配置各运行五次计时。

| 配置 | 三个稳定指针，ns／调用 | 同一指针的显式窗口，ns／调用 |
| --- | ---: | ---: |
| 源顺序 | 44.52 | 50.56 |
| Guarded 恒等 | 9,091.65 | 76.05 |
| 盒式 `i-k-j` | 9,892.15 | 1,233.83 |
| 参数化 `i-k-j` | 8,849.11 | 73.55 |
| 盒式交换后 `2×3` 分块 | 10,435.31 | 1,783.94 |
| 盒式分块后完整分区 | 10,797.52 | 1,718.86 |
| 参数化交换后 `2×3` 分块 | 9,381.84 | 115.11 |
| 参数化分块后完整分区 | 9,235.77 | 116.13 |

表中为每次调用 CPU 时间的中位数。`clock()` 只覆盖重复内核调用；数组初始化、校验和与打印在区间之外。每种配置先校准重复次数，使计时至少约 0.08 秒，再取五次样本。每次独立核对 Word 校验和及五个公开出口；另外对发出的 Clight 诊断一次，确认七种合法候选实际进入快路径。完整数组的行为验证见[累加实例](deep-affine-accumulation.md)，这些计时次数不并入其正确性调用数。

窗口实验的源显式使用一个指针，在偏移 512、1,024 的区域读取数据。单指针实例使用已有的地址单元对应与静态依赖证明。框架没有从一般三指针程序自动推导或转换到这种布局，两种源各有自己的模型与完整程序保证。

三指针版本对完整描述去重并移除反向比较，保留实际源足迹的平方扫描。恒等候选也约为源成本的 200 倍，说明这个小输入上，仅更换候选不能消除主要开销。窗口布局没有跨指针扫描；参数化交换也不枚举静态盒，测得接近恒等候选的成本。参数化分块通过较紧的运行时范围和空块检查，窗口实验约为源成本的 2.3 倍；盒式分块约为 35 倍。盒式候选及其分块仍较慢。这是对上述实验和生成代码的解释，不是一般的成本定理。

与提交 `31574fc` 的保存版本比较，三指针版的实际 Clight 地址比较从 17,640 次降到 5,292 次，减少 70%；参数化交换的 CPU 中位数从 29.42 微秒降到 8.85 微秒。两个版本的源文件相同；源顺序和窗口布局全部八种配置的汇编也逐字相同。因此不能把窗口版两轮计时的变化归因于扫描改进。比较记录为 `build/native-affine-nest-scan-cost-comparison/report.json`，旧版保存在 `/tmp/guard-parametric-tile-verified`。检查保持相同前提的证明见[扫描精简](deep-affine-scan-cost.md)。

表中实验仅覆盖一个数据在缓存中的小内核，计时环境为共享 Linux x86_64、AMD Ryzen 7 7800X3D 主机；没有绑定 CPU、控制频率或做系统性规模曲线。因此不能宣称整体加速、精确的通用倍率或某候选始终较优。后续应分别解决实际指针检查的成本、参数化候选生成、控制出口恢复，并在更大域和多种布局上测量。

`make native-affine-nest-accumulation-cost` 可重建两个实验。记录在 `build/native-affine-nest-accumulation-cost/report.json` 与 `build/native-affine-nest-accumulation-window-cost/report.json`，包含源码、候选、汇编、二进制、Clight、日志摘要及全部原始样本。
