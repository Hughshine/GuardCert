# 建议推进的贡献与验收

2026-10-02。本文提出一条有优先级的研究路线；它不是已实现能力或已确认的新颖性结论。当前实现边界见 [候选条件化](candidate-conditioning.md) 与 [CompCert 接入](compcert-integration.md)。

当前主线是以 PolCert 为功能与证明架构参照，在 CompCert 中实现有动态前提的多面体变换，并闭合完整程序保证。允许为机器语义重实现状态、IR、算法和证明；验收看基本功能与语义保证，见 [多面体接入目标](polcert-integration-target.md)。通用条件编译、实际内存规则、嵌套 Loop lowering、真实 C 前端整循环宿主及原生零次迭代规则已经实现。实际 PolOpt 的端点也已接到[参数化的完整程序证书](polcert-optimizer-regions.md)，具体循环证书尚未实例化。[CInstr 入口审计](polcert-context-audit.md) 另证明旧非空 wrapped 入口不可执行，新显式参数实例则已有真实内存执行见证。直接 Clight 的可组合嵌套源进展已接入提取驱动；[原生矩阵循环交换](native-matrix-interchange.md) 又完成一个带安全动态检查的 2×2 仿射 store 模板，重排实际 Mem.store 并保留完整出口，五个函数通过原生验证。下一步是扩展调度证书与候选来源，减少固定模板的实例证明；private temporary、一般 tiling 和条件推断仍未完成。下面的首版范围保留为研究路线，不能代替当前实现边界。

[可执行有限调度检查器](schedule-checker.md) 与[外部点顺序入口](untrusted-point-schedules.md) 已扩展候选来源：工具只提交自然数点序列，检查器构造交换证书，语言编码器生成真实 Clight 展开代码并修复精确出口。参数化完整程序定理不信任提案；原生测试覆盖全部 24 个四点排列与七个错误提案。源域仍固定为 2×2，因此下一步应分离通用矩形域／body 编解码接口、加入读改写依赖及动态域对应证书，而不是把有限排列检查称为一般多面体编译器。

[树形原子检查接口](clight-signed-cancellation.md) 已接入相同完整程序宿主：signed32 的乘法取消实例使用 signed64 检查并保留溢出输入的回退。它和实际 Loop 动态合成共用公式合成器；这项复用没有闭合多语句循环区域的完整程序链。

[递归 Loop 桥接](polcert-nested-clight.md) 已支持指定 scratch 深度的嵌套循环和公共 temporary frame，检查与参数／live 集合以及 scratch 之间的冲突。下一步重点转为具体内存／指令实例、外围 live 与函数声明的宿主证明、tiling 边界运算、候选进展及区域 simulation。

[具体数组桥接](polcert-array-clight.md) 已使用真实 `CInstr/CState` 和 CompCert load/store，替代抽象基本指令执行假设。[有限语句区域宿主](clight-statement-regions.md) 已完成正常出口、精确 temps 和双向 `Mem.extends` 内存对应的完整 Clight 模拟，并有实际 C→Asm 例子。PolCert 仍需要private temporary/live frame 和实际优化器的候选进展；有限区域宿主不能被当作这一整条链已完成。

[具体动态调度包](polcert-schedule-regions.md) 已把运行时下标的双写候选装入同一接口并提取运行。该实例推动接口区分检查域和语言适配前提：范围或无溢出前提可以在 guard 接受后才允许源解码。性质库、公式合成、真实 CInstr 调度定理与完整程序宿主在这一路径中实际复用；这仍是工程与机械化进展，尚未建立候选条件推断算法或独立新颖性结论。

[片段内部进展接口](region-protocol.md) 已提供语义无关协议、有限 Clight 宿主接入及严格计数循环实例。循环路径的完成结果可还原为源语句执行，零次迭代无需 body 访存前提。宿主现在通过显式模拟索引实际消费循环协议，零次迭代条件可替换整个循环，并具有完整 C→Asm 定理；真实 C 前端包装已经接通；private temporary、实际 PolOpt 候选进展与出口关系仍需分别解决。

## 建议作为主问题

> 给定原片段和独立候选，在指定的前提域与可用观察下，寻找能安全执行的充分条件，输出可核对的条件正确性证书、实际检查代码及完整程序精化保证。

当前实例限定为顺序 CompCert、入口回退、有限片段与可嵌套的严格 signed32 计数循环；这些片段可以出现在宿主循环中。宿主程序仍可以有调用、循环和复杂外围控制流。目标覆盖整数表达式、路径 rewrite 与一类真实 load/store 片段，候选来自规则、人工修改或不受信任工具。

关键设计选择是：条件推断从开始就要知道哪些输入可得到、哪些检查可安全执行、什么证据只能由静态分析提供。若只先找到任意逻辑 Q，再让使用者逐实例解决机器编码与执行安全，仍会留下本项目要消除的主要证明工作。

## 必须比较的新增先例

[CompCert-loop 的 2026 年预印本](compcert-loop-comparison.md) 已使用抽象行为接口，把大步结构变换接到 CompCert 的完整程序定理，包括循环展开和 unswitching。本文的完整程序组合与语义性质接口不是独立的新颖性依据；应检验可执行前提合成、实际机器语义下的条件调度与出口修复。

新发现的 [VLIM，DATE 2026](vlim-comparison.md) 已提供很接近的 verified rewrite algebra 与 statement-to-function 提升。当前仅核对仓储与会议论文索引，runtime guard 的具体意义尚未确定；不能继续把证明组合本身当作足够的新颖性主张。

除了 [COVE/cSTOKE](https://theory.stanford.edu/~aiken/publications/papers/oopsla15a.pdf)、CGO、CoreJIT 和 Peek，还需比较：

- Cousot、Cousot、Logozzo，[Precondition Inference from Intermittent Assertions and Application to Contracts on Collections，VMCAI 2011](https://pcousot.github.io/publications/CousotCousotLogozzo-VMCAI-LNCS-6538-pp150--168-Jan-2011.pdf)。论文同时研究静态契约推断与可由调用者观察、没有可见副作用的运行时检查生成。其非确定性契约允许保留有成功执行的输入，不能直接当作本项目要求的普遍条件精化。
- Dillig、Dillig、Chaudhuri，[Optimal Guard Synthesis for Memory Safety，CAV 2014](https://www.cs.utexas.edu/~swarat/pubs/CAV14-extended.pdf)。基于 abduction、前后向分析和 ghost allocation/offset 信息生成实际程序变量上的 guard，并相对给定循环不变量证明 Pareto 最优性；成本关注变量数量与条件强弱。研究目标是被保护代码的内存安全。

本次核对了两篇全文的引言和方法重点，没有构建其 artifacts。因此“考虑可执行性”“有代价的 guard 合成”“消去不可观察 ghost 信息”本身也不能被当作新主张。应比较二程序关系、机器算术、检查自身的行为与实际 CompCert 证明链，以及我们具体新增的算法能力。

## 三项互相支撑的候选贡献

| 项目 | 具体产物 | 为什么需要 | 贡献强度判断 |
| --- | --- | --- | --- |
| 受执行约束的条件推断与验证 | `source/candidate + entry facts + allowed observations` 到前提及局部证书；受限条件域中的搜索、反例与拒绝诊断 | 成立的逻辑条件不一定有安全、可实现的检查 | 核心候选算法贡献；须明确区别于 COVE、契约推断和 abduction guard synthesis |
| 通用的已验证检查编译与残留条件处理 | 类型化 AST 到真实 Clight 控制流；validity、短路、静态消解、接受能力的定理 | 把每条规则手写 guard lowering 变成库级算法 | 先完成的基础设施与机械化贡献；单独完成不足以支撑宽泛的新框架定位 |
| 条件证书到完整程序的可复用连接 | 同一个证书支持静态应用、混合检查、全部动态检查；至少算术和内存两类实例 | 用户提交局部候选即可获得明确宿主范围内的保证 | 综合系统与证明贡献；局部到全局的定理形式已有先例，应展示实际复用与语义覆盖 |

这三项应服务一个系统，而不是分别新增几个占位 record。条件推断可以是不受信任的 oracle；可信边界包含局部证书核对、检查编译及宿主组合。测试与 profiling 可以引导搜索和选择，但不能承担普遍正确性。

## 关键约束与定理

令 F 为本位置可靠的入口事实，S 为原片段，T 为候选，A 为充分条件，G 为检查代码。首版需建立以下义务：

```text
F ∧ A                  ⇒ S/T 的局部精化
F ∧ source-safe        ⇒ G 的求值安全、终止且保留可见入口状态
F ∧ G accepts          ⇒ A
G rejects              ⇒ 从对应入口运行 S
以上证书和 Host 前提    ⇒ guarded fragment 的完整程序精化
```

这里的 `source-safe` 应在实际宿主定理中定义，不能用表达式有某个值替代所有片段的安全执行。F 也必须来自已验证分析、宿主入口关系或经核对的证书，不能假定用户注释为真。

条件 AST 的求值失败与布尔 false 必须分开：失败在否定下仍不能变成接受。源/候选精化、检查定义性和检查状态保持是分别需要的证明。当前标量 lowering 契约要求抽象执行得到 `Some b`；通用 lowering 应支持最终把 `None` 转为回退，同时保留内部 validity。

还应给出适用域内的接受能力说明。例如，在所有原子检查可定义求值时，检查与公式有真/假对应；仅有接受可靠会允许永远回退。搜索算法先报告非空接受域与边界实例，后续再尝试相对于固定 predicate basis 的完整性或最优性，避免承诺任意程序的最弱前提。

## 可观察信息应成为推断输入

理论状态里的 block ID、permission 或对象 extent 不等于 C 程序能够读取的信息。推断器需要一个允许的观察库，每个原语有真实表示、安全条件和效果证书。第一版可以只有已定义的整数 temporaries、范围/相等/无回绕，以及携带布局证据的数组索引。

如果两个满足 F 的安全入口在允许观察上完全相同，但候选只在其中一个入口正确，那么仅依赖这些观察的可靠 guard 不能接受这一观察类。这个基本限制不是独立的新理论结果；它可指导算法拒绝、请求额外静态证据或生成更保守条件，而不是假造读取抽象 metadata 的代码。

检查有自己的路径。例如，原代码只在 `n > 0` 时读取 `*p`，入口 guard 就不能无条件先读取 `*p`。把这类路径事实用在检查生成中，与只证明最终算术公式为真有实质区别。首版限制读取原语，不假定 `p != NULL` 已足以保证可读取。

## 第一批实例

| 实例 | 应由框架自动完成 | 检验的难点 |
| --- | --- | --- |
| 人工候选 `(x+x)/2u → x` | 发现并核对 `x <= 0x7fffffff`，生成检查 | 条件来自代码对；机器模算术；输入溢出时回退 |
| 相同规则在已证明范围下使用 | 消去全部或部分检查，复用同一局部证书 | 静态事实可靠性与残留条件处理 |
| 带加减、比较、否定的条件组合 | 自动 lowering，保留 validity 与短路 | 检查本身回绕、underflow、求值失败不得被否定为接受 |
| `a=A[i]; A[j]=v; b=A[i] → a=A[i]; A[j]=v; b=a` | 从布局/范围证据与索引关系验证不相交，生成可实现的检查，插入真实 load/store 片段 | 字节 footprint、权限、索引到地址的对应、状态与控制流组合 |

最后一个例子要明确数组分配、chunk、索引范围与地址不回绕的证据；不能仅从 `i != j` 对任意指针算术推断不相交。先做单一数组或带布局证书的片段，再扩展到不同对象及 runtime metadata。现有 `CompCertMemoryRule.v` 只有真实 load/store 端点，尚未提供这一整条保证。

函数身份特化与库实现快速路径可作为下一批实例，需要加入 genv、调用和代码身份接口。完整去优化、一般循环前提推导、表示迁移和不同正确性目标宜分成后续扩展，而非第一版的成功标准。

## 应怎样动手

1. **先实现实际 condition compiler。** 用 Clight 语句控制流表达短路；先支持现有 unsigned32 加减、范围、相等、NoOverflow 和布尔组合。修改 lowering 接口使 `None` 能回退，证明检查安全与入口状态保持。允许结构化编译和临时变量方案，但必须处理代码增长或 freshness/frame。
2. **加入带证明的静态残留处理。** 从 F 消去原子条件，证明 F 下残留条件足够；把输出交给同一个 compiler。用一个规则的静态、混合、动态三种应用检查复用。
3. **实现受限的候选条件搜索。** 先以有限的 predicate basis 处理纯整数片段。搜索器提出条件，验证流程核对条件精化并输出证书；不支持的操作或无有用证书时拒绝。用全宽语义验证，不能将小位宽枚举当成 uint32 的证明。
4. **接入真实内存片段。** 为数组访问实例完成实际检查、候选、fallback 和整程序链。这个阶段检验公共算法是否真能跨越算术与内存，而非只在同一类标量恒等式上复用。

第一步的三出口结构化编译已在 `AbstractGuard.v` 实现：条件为真、为假、无法检查分别有 continuation；否定只交换前两个出口，最终无法检查的出口运行原片段。Clight 与实际 PolCert `Loop` 均已实例化。当前树形 lowering 复制叶子；若进一步采用临时状态或共享 CFG，仍须证明状态关系及入口/label 对应。

## 研究验收与停止条件

需要记录条件接受率、检查成本、候选收益、代码增长、分析/证明检查开销，以及增加新规则需要多少专属证明。条件搜索超时、不支持信息、条件为假和实际检查无法完成，应分别报告。IR 操作数可以作为成本估计，不能被宣称为真实机器运行时间的已证明上界。

有说服力的结果是：没有逐实例手写 guard lowering，条件推断确实消费可执行性约束；静态和动态应用共享证书；算术与内存实例共享公共生成链；提取后的 CompCert 编译器实际运行并获得完整程序定理。

若最终只有新的 record、几条手工条件规则，或仅把先例算法重新实现而没有更明确的语义保证与复用收益，则应降低研究主张。若有可运行的已验证条件编译库、可靠候选验证接口和端到端异质实例，则至少形成具体的机械化与系统贡献；更强的算法定位需继续与最接近工作做逐例对照。
