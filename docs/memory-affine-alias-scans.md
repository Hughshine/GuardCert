# 一般一维仿射地址检查与有状态的框架接口

这一扩展把循环式地址检查从两个指针的 `p[i]`／`q[i]` 推广到一个计数轴上的 signed 仿射下标、任意有限数量的参与指针及多条赋值。源和候选仍使用实际 CompCert 内存；调度与机器代码检查保留在原有统一入口中。检查器可以改变自己的临时变量，框架通过公共状态关系把检查、候选和原片段组合起来。

例如，实际 C 输入可以包含：

```c
for (; i<n; i++) {
  p[2*i] = q[3*i+1]*alpha + r[4*i+2]*beta;
  r[4*i+2] = p[2*i] + i;
}
```

候选可以来自人工输入、外部调度器或已有代码生成器。以下输入要求按反向迭代顺序生成候选，并声明相应的坐标反射：

```lisp
(schedule ((negative-coordinate 0) ordinal) ((reflect 0)))
```

`negative-coordinate` 使用源包提供的完整参数前缀和维数构造调度系数。它只是非可信输入侧的便利记法；真实域、指令、读写访问和依赖由源提取及独立检查器核对。

## 从前提到可执行检查

源包提供每一条原始读写访问的指针标识符、数学仿射编码和实际 Clight 下标表达式。当前下标可以使用原迭代变量、有符号常量、加减和常量乘法。外部稳定标量可以参与 RHS 数据计算，但尚不能参与这一新路径的地址下标。

编码器先生成短路计数检查，要求原迭代变量为零、次数为正，并满足经访问范围和后端核对的上界。通过后，它为不同指针之间的每一对原始访问生成两层私有循环。例如，对写访问 `p[2*i]` 和读访问 `q[3*i+1]`，它比较所有：

```text
&p[2*x] != &q[3*y+1]    0 <= x,y < n
```

比较为假会清除累计标志。全部扫描结束后，标志为真才进入候选，其他情况执行原循环。同一个指针的不同逻辑下标由已有物理地址分离证明处理。这个实例对不同逻辑指针要求所有活动单元分离，包括两个只读指针之间，因此只读别名仍可能保守回退。

检查只计算地址并比较，不读取数组中的数据。成功的源执行提供每个实际访问单元的有效指针和 Mint32 对齐证据；它不要求指针覆盖完整逻辑窗口，也不要求不同指针位于不同 CompCert block。对齐与地址不等建立四字节范围不重叠，同一 block 中的分离切片可以接受。

`GuardMemoryAffineRangeAddress.v` 将原下标中的迭代变量重命名为私有扫描计数器，并证明数学下标与真实 Clight 指针地址对应。中间整数运算允许按 CompCert 机器语义回绕；最终编码下标和实际偏移仍须通过范围证明。例如：

```c
q[(2147483647*i+i)-(2147483647*i)-i+1]
```

其最终仿射编码为常量 1，地址对应不需要声称每个中间加法都无溢出。

候选所需前提包括合法计数范围及源实际活动足迹上的 `NonAlias`。这两个性质成立之后，候选还必须通过独立的域及依赖验证。比如下面的循环存在跨迭代依赖：

```c
for (; i<n; i++) {
  p[i] = q[i]*alpha + beta;
  q[i+1] = p[i] + q[i+1]*beta;
}
```

即使 `p`、`q` 不 alias，反转或按语句位置拆分仍可能改变结果。alias 检查本身不给出这些候选的调度正确性证书。

## 不解释具体语义的核心

`theories/StatefulGuard.v` 中的 `stateful_language` 让具体语言选择：

- 状态、命令、检查代码和观察值的类型。
- 命令执行关系，以及返回布尔结果和检查后状态的检查执行关系。
- 执行检查后、在检查后状态执行所选命令的条件构造器及组合证明。

`projected_guard_encoding` 将前提编码成该语言的检查代码。编码证明需要给出检查安全执行的域和公共状态关系，并证明在这个域中检查会产生结果、保持公共状态关系，以及接受时在**检查后状态**建立前提。拒绝只表示保守回退，不携带前提为假的证明。

`stateful_guard_preservation` 再要求三个语言实例义务：源执行推出检查域；公共状态关系可以运输源的观察；候选在前提下保持源观察。结论是原命令的每个观察可以由带检查的命令产生。核心不知道整数、alias、内存块或源语言的语法。

`StatefulGuardComposition.v` 提供短路合取编码。第二个检查的执行需要域在公共状态关系下稳定；两个检查的关系需要可组合；第一个性质需要经过第二个检查后仍然成立。这些义务显式保留在接口中，避免错误地组合会破坏彼此前提的有状态检查。保守检查不能通过布尔取反自动得到否定前提。

`GuardMemoryStatefulLanguage.v`、`GuardMemoryStatefulEntry.v` 和 `GuardMemoryStatefulComposition.v` 用实际 Clight 检查执行实例化这些接口。状态包含 genv、env、temporaries 和 Mem；公共状态关系保留 genv、env、Mem 以及源标识符，允许新鲜私有计数器和标志改变。观察是公开出口 temporaries 与等价内存，具体语言负责证明这种观察满足宿主要求。

`GuardMemoryStatefulRule.memory_projected_private_rule_stateful_sound` 实际调用抽象核心定理，得到已有 `projected_region_contract`。新的仿射地址编译路径消费这个定理。片段宿主进一步提供内部小步进展、出口关系及完整程序模拟；抽象核心定理本身不替代这些语言义务，也不单独构成完整程序定理。早期逐元素检查路径仍使用它已有的直接具体组合证明。

## 接入路径与边界

```text
实际 Clight 源区域
  → 已验证的源包及实际访问足迹
  → 非可信候选调度或 Loop
  → 已验证的源／候选域和依赖检查
  → 仿射地址扫描编码及有状态核心组合
  → projected_region_contract
  → 统一区域宿主和 CompCert 后端
  → compile_memory_unified_regions_correct
```

统一多指针入口依次尝试原来的逐元素双指针扫描、新的一维仿射扫描和已有有限枚举路径。新的扫描只构造至多 32 条原始读写访问之间的检查；超出这个资源上限会继续尝试旧路径。旧路径也拒绝时保留源区域。32 是静态代码构造上限，不是运行时次数上限。

设原始访问数为 A、运行时次数为 n，当前检查代码规模为 O(A²)，运行时间为 O(A²n²)。重复访问尚未去重，地址扫描尚未短路退出，没有性能加速声明。次数还受逻辑窗口 1024、各仿射访问的范围及候选检查约束。它们不代表实际分配长度。多轴扫描、地址中的外部参数、弱化只读别名条件和更高效的分离检查继续推进。

复现入口为 `make native-memory-affine-alias`。完整 CompCert 汇编结果由 `scripts/native_memory_affine_alias.py` 核对；`native_memory_affine_alias_paths.py` 独立执行加标记的 Clight 打印副本以记录分支选择。后者的 GCC 诊断不作为 CompCert 汇编执行证据。

## 本轮验证

2026-10-03：293 个 CompCert 适配模块、七个 lowering 模块及两个抽象核心模块的全量 Rocq 重编译与假设审计通过，442 个证明源码哈希一致。抽象核心的保持定理与短路合取编码均没有全局公理。指令桥、validator 和完整编译器分别保留原有 7、12、42 项假设；完整编译器的集合仍精确等于既有基线的并集。提取编译器 SHA256 为 `3e7fd197d72c101cb55b6afe8cf54a073f9bca38b0db4bffa6b6e14921713341`。

独立 GCC 参考程序已与机器字模型核对 266 次完整调用和 18 次资源边界调用。输入包含非单位步长、逆序及常量下标、三指针读写链、实际别名和同一 block 内不同切片、极值 RHS、空循环中的未初始化操作数，以及总原始访问数为 32、33、65 的资源边界。

十组主配置和两组资源配置共 2696 次完整 CompCert 汇编调用通过，完整调用方数组和公共计数器与 GCC 及独立模型一致。五组正常配置包括生成 identity、按语句位置拆分、生成反向、直接 Loop identity 和直接反向；五条拒绝路线覆盖常量坐标、错误反射映射、无效坐标、资源耗尽及伪造证书。常量坐标与错误反射在本输入上全部拒绝；测试允许其他源在已验证的次数 1 条件下接受这些提案，不把拒绝模式当作通用语义规则。
